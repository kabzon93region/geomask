# geomask v1.13.2 — IP-заблокированные googlevideo-рёбра через VPN (ytvpn)

## Суть

Часть edge-хостов `rr*.googlevideo.com` (CDN YouTube) блокируются **по IP** — zapret/DPI тут
бессилен (он перепаковывает пакеты, а не обходит IP-бан). Такие хосты нужно пускать **через VPN**.
Проблема была в порядке правил: `RULE-SET,ytdirect,DIRECT` ловит весь `googlevideo.com` суффиксом
раньше, чем `mtrickle,VPN`, поэтому даже внесение хоста в «To VPN» не помогало.

## Что добавлено

- **`ytvpn.yaml`** — отдельный ruleset точных `DOMAIN` для IP-заблокированных googlevideo-рёбер.
- **Правило `- RULE-SET,ytvpn,VPN` стоит ДО `ytdirect,DIRECT`** в конфиге mihomo — конкретные хосты
  уходят в VPN-группу, а весь остальной `googlevideo.com` — как раньше, на DIRECT (zapret).
- geomask устанавливает `ytvpn.yaml` из курируемого списка **только если он пуст/отсутствует**,
  поэтому добавленные владельцем хосты в `/etc/mihomo/ruleset/ytvpn.yaml` переживают обновления.
- `--check` (шаг 5) проверяет наличие правила `ytvpn->VPN`.

## Стартовый список (6 хостов из теста стратегий 30.10)
```
rr4---sn-4g5e6nze  rr4---sn-q4flrnsl  rr2---sn-q4fl6ndl
rr1---sn-q4fl6n6y  rr16---sn-axq7sn76  rr1---sn-xguxaxjvh-gufl   (.googlevideo.com)
```

## Как добавить ещё заблокированный хост
Открыть `/etc/mihomo/ruleset/ytvpn.yaml` на роутере, добавить строку
`  - DOMAIN,rrN---sn-XXXX.googlevideo.com`, затем `curl -X PUT http://127.0.0.1:9090/configs -d '{"path":"/etc/mihomo/config.yaml"}'`.
(Или сказать агенту — внесёт в курируемый список geomask.)

## Обновление
```sh
curl -fL -m 60 -o /tmp/geomask.sh 'https://cdn.jsdelivr.net/gh/kabzon93region/geomask@v1.13.2/geomask.sh' && sh /tmp/geomask.sh
```

## Примечания
- На уже настроенном роутере правило в `config.yaml` появляется только при генерации НОВОГО конфига
  (шаг 3 сохраняет существующий). Для текущего роутера правило добавлено вручную (v1.13.2-эквивалент)
  и закреплено в шаблоне на случай переустановки.
- Тесты: S18 (wiring + порядок правила до ytdirect + keep-existing). Всего 114 проверок.
