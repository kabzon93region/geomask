# geomask v1.6.1 — mark-clear: защита маршрута от окна пересадки

**Дата:** 2026-10-18 · **Тип:** фикс (усиление geomask-guard) · **Обновление:** шаг sync
мастера или `sh /tmp/geomask.sh --reinstall --yes`.

## Почему

Инцидент 18.10, 23:27–23:35: на AI-устройстве (`.125`) перестали грузиться сегменты HLS-видео.
Причина — **окно уязвимости ≤5 минут** при пересоздании правил magitrickle:

1. magitrickle пересоздаёт свой блок `ip rule` → база встаёт ниже нашей (сегодня: `19979 → 19537
   → 19416`) **и** его цепочки заново вставляются в `PREROUTING` — исключения `geomask-excl`
   оказываются ниже прыжков `MT_*`;
2. в этом окне пакеты ai-устройств снова получают метку `0x4d61xxxx` → fwmark-правила перехватывают
   их → трафик уходит в основной туннель и выходит с **реальным РФ IP**;
3. watchdog возвращает порядок ≤5 минут, но пользователь в это окно попал: CDN видео-хостинга
   (`hls.intrdb.com`/`cdn361`/`failback.turkserial.co`) **не отдаёт сегменты с РФ-эгреджа**
   (проверено:DIRECT/MAIN — таймаут 30 с, 519 Б/с; через AI-ноду — 200 за 2,5 с, 722 КБ/с).

Симптом на сайте: плеер крутит фолбэки `hls → cdn361 → failback` и видео не стартует.
(Отдельно: `ERR_BLOCKED_BY_CLIENT` в консоли — это блокировщик рекламы в браузере, к роутеру не относится.)

## Что сделано

Новый слой **(A2) mark-clear** в `geomask-guard.sh`:

- собственная nft-таблица `ip geomask_excl` (невидима для magitrickle и fw4, переживает любую
  перестройку `PREROUTING` — в отличие от исключений-`return`, позиция которых зависела от порядка
  в общей цепочке);
- цепочка `prerouting`, **priority -149** — сразу после mangle magitrickle (`-150`) и **до**
  метки AI-DNS `0x64` (`-110`);
- одно правило с named-set: `ip saddr @excl_ips meta mark and 0xffff0000 eq 0x4d610000 counter
  meta mark set 0` — стирает **только** метки magitrickle (`0x4d61xxxx`), метки zapret и AI-DNS
  не затрагиваются;
- guard синхронизирует элементы set из `/etc/geo-devices.list` на каждом прогоне (добавляет
  недостающие, удаляет осиротевшие).

**Итог:** даже пока watchdog не пересадил `ip rule`, пакет ai/bypass-устройства к моменту выбора
маршрута не имеет метки magitrickle → fwmark-правила не совпадают → решает только наше
`from <ip>` → таблица `101`/`main`. Окно уязвимости закрыто полностью (не «≤5 минут», а «нет в
принципе»); watchdog остаётся гигиеническим слоем (порядок правил, сброс conntrack, table 101).

Также в этой версии (из v1.6.0, повторно для полноты тега): nft-исключения `geomask-excl` в голове
`ip mangle PREROUTING`, watchdog `ip rule`, приоритеты `19900/19901/19902`.

## Проверка после обновления

```sh
sh /tmp/geomask.sh --check                    # pass=7 fail=0
nft list table ip geomask_excl                # chain prerouting + set excl_ips + правило
nft list chain ip geomask_excl prerouting     # counter растёт при трафике с ai/bypass-устройств
ip route get 8.8.8.8 from 192.168.0.125 iif br-lan mark 0x4d616769   # dev AI table 101
```

Повторный сценарий инцидента: открыть видео/2ip с `.125` **в момент** строки
`geomask-guard: ip rules re-seated` в `logread` — маршрут должен остаться `dev AI`.

## Известные ограничения

- Правило mark-clear стирает именно диапазон `0x4d61xxxx` (пространство меток magitrickle,
  `startMarkTableIndex: 0x4D616769`). Если владелец сменит `startMarkTableIndex` в конфиге
  magitrickle на иной стартер — маску в guard надо обновить.
