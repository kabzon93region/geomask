# geomask: журнал исполнения плана массовой готовности

Дополняет [план исправлений](2026-11-18-mass-readiness.md). Одна запись на партию: коммит,
что закрыто, чем доказано, что осталось. Правило то же, что в плане: «зелёный локальный
тест» не закрывает стендовые gates.

## Партия 1 — updater trust/integrity (U01–U03)

- Коммиты: `ff51cc7` (основное), `553ae7a` (закрытие замечаний ревью).
- U01: кеш каталога переехал из `/tmp` в приватный `/etc/geomask/cache`; недоверенный кеш
  (ссылка, не-файл, чужой владелец, запись для группы/остальных, путь вне приватного
  каталога) не читается и не перезаписывается; сам каталог тоже проверяется. Пути
  назначения из каталога обязаны быть абсолютными, нормализованными и внутри
  `INSTALL_ROOTS`; установщик (`step2_apply`) удаляет кеш после установки, иначе он
  описывает предыдущий релиз.
- U02: staging записывает preimage-digest, коммит под тем же локом сверяет его заново;
  правка владельца, удаление и файл, созданный в промежутке, не затираются без `--force`.
- U03: любая ссылка на пути установки (файл или родитель) — отказ до первой записи.
- Доказательства: `tests/test_module_update.py` 47 → 64 (14 поведенческих RED на старом
  коде, затем 3 теста на замечания ревью); `tests/reinstall_manifest.py` 23 → 27
  (негативные тесты политики); build/RPC parity, `sh -n`, `py_compile`.
- Осталось: Linux UID/`O_NOFOLLOW`-проверки, `--force` vs policy на реальном росте,
  перенос `BACKUP_ROOT`/`LOCK_PATH` из `/tmp` (MINOR ревью) — см. партию 3.

## Партия 2 — один writer и один CAS для console/slot (C01, C11)

- Коммит: `42c64c7`.
- C01: откат консоли больше не коммитит preimage безусловно. Он проверяет, что живые байты
  всё ещё его собственный postimage, и коммитит с `--expect-sha256`; чужой коммит или
  отсутствующий postimage → `restored:false, conflict:true`, запись не выполняется,
  preimage остаётся рабочей копией.
- C11: `geomask-slot-patch.py` больше не открывает живой конфиг — печатает байты-кандидаты
  в stdout, действие в stderr; backend коммитит их через `geomask-config-tx.py` с CAS,
  необъявленный `.bak_slot` удалён. `_mihomo_reload` возвращает код контроллера вместо
  «успеха за sleep».
- Доказательства: `tests/test_console_tx.py` 10 → 12, `tests/test_slot_patch.py` 9 → 12;
  оба RED до правки (в т.ч. «rollback overwrote a commit made by another writer»).
- Осталось: slot→TX на живом mihomo (стенд), `_rs_restore_cron`-подобный CAS для
  restart-preimage (I04, вторая половина).

## Партия 8 — reload-proof, AND/OR, dhcp, syncd, release, start order (C04/C07, G02, G03, P11, P10, P12, R01)

- Коммиты: `16c3ed7` (C04/C07), `1f7baba` (G02/P12), `3c14bfd` (G03), `fd28828` (R01),
  `c0bf739` (P11), `1aef885` (P10).
- C04/C07: «байты записаны» больше не равно «runtime применён». Новый
  `assets/geomask-reload-state.py` держит маркер pending (попытки, время), повторяет reload
  на каждом следующем прогоне, снимает маркер только после успеха, вливает `reload/pending`
  в состояние и отдаёт rc 1, пока runtime не подтверждён. Sync отдаёт в состояние все четыре
  флага (VPN/AI/ytvpn/bulk) и выходит 1 при pending; AI-DNS пишет include, перезагружает
  firewall и читает обратно `nft list table inet geomask_ai_dns` — `state=ok` только после
  этого, при отказе `state=pending`, RPC отвечает `ok:false,state:pending`, а идентичный
  следующий прогон повторяет reload вместо cmp-выхода.
- G02: обход правил стал трёхзначным. `AND` с `any()` матчил по одному условию, а
  NETWORK/DST-PORT/PROCESS-* условия возвращали «ложь». Теперь `true/false/unknown/unresolved`:
  AND требует все (иначе «сработает при…»), OR — любого true (иначе «возможно при…»),
  RULE-SET внутри AND/OR вычисляется по payload, IP-правило без разрешённого адреса не
  считается ложным и не обрывает обход (в ответе «не проверено: №N IP-CIDR»), правило по
  порту больше не проскакивает к MATCH. Шаг трассы для условного попадания — warn, не ok.
- P12: ответ контроллера больше не пишется на overlay целиком. Оба raw-дампа режутся
  `head -c cap+1`, существующая проверка размера по-прежнему даёт «response too large»
  (bytes = cap+1 доказывает обрезку).
- G03: static lease создаётся проверяемыми записями. Поиск секции — по точному MAC (разбор
  значений uci, а не `grep` подстроки), существующий lease обновляется вместо дублирования,
  каждый `uci set` проверяется, секция коммитится только если mac+ip прочитались обратно,
  владение пишется только после этого; при отказе секция удаляется, dnsmasq не трогается.
- P11: watchdog перестал ждать событие, которого может не быть. Есть стартовый reconcile,
  после каждого прогона сравнивается digest содержимого каталога и при изменении во время
  прогона выполняется ограниченный catch-up (3 прохода, дальше — cron как backstop),
  fallback-digest хеширует содержимое, а не `ls -l`.
- P10: hook `/etc/hotplug.d/iface/99-default-vpn-route` ставится до `safe_mihomo_restart`,
  а не в step5 — первый старт mihomo больше не остаётся без хука, восстанавливающего
  default в таблицах 100/102.
- R01: публикация идёт через gate. `publish` больше не запускает raw `unittest discover` и
  мутирующий `check_build`: `--verify-only`, RPC-манифест, `tests/testgate.py run`,
  песочница; `verify` без `--full` честно пишет «установка НЕ проверялась», а с `--full`
  называет песочницу, прогнанную на скачанном файле.
- I08: присутствие больше не выдаётся за актуальность. `STEP2_FILES` — ровно тот набор из
  27 путей, который пишет `step2_apply` (включая doctor, lock-helper, updater, помощники
  adopt/reload и каталог); проверка шага 2 идёт по нему и пропускает пути снятых модулей так
  же, как `save_stream`. `step_check_is_authoritative`: для шага 2 пройденный check больше не
  отменяет apply (presence не доказывает свежесть), остальные шаги сохраняют быстрый путь.
- Полный gate на этом SHA: 94 модуля, 1362 теста (1333 выполнено, 29 allowlisted skip),
  0 fail, 0 timeout, verdict PASS (лог `gate15`, `--timeout 4200`: дефолтные 600 с малы для
  `test_reinstall_phase2b`, 2181 с на этой машине).
- Test-infra: `test_sandbox_guard` один раз упал в полном прогоне на `WinError 2` при запуске
  python (в отдельном прогоне проходит), добавлен один повтор с явным путём интерпретатора.
- Доказательства: новый `test_reload_state` 10, `test_backend_safety` 17 → 22 → 25,
  `test_sync_ytvpn` 3 → 5, `test_doctor` 64 → 73, `test_console_diag` 29 → 30, новый
  `test_release_tooling` 5, `test_initd_contract` 11 → 14, `test_install_safety` 46 → 49.
  Все новые тесты RED на старом коде (кроме пары «замков» на точность, отмеченных в
  коммитах). Стенд: реальный firewall/nft, netifd already-up, LAN-client dataplane —
  остаются OPEN.

## Партия 7 — guard G06/P01, adopt I05, вердикт владения N04, prune I11

- Коммиты: `29c886f` (G06), `5cd5112` (P01), `4a22dc4` (I05), `32db49f` (N04), `cc4c14c` (I11),
  `b068e57` (синхронизация write-set gate с IPv6-writer'ом из партии 6).
- G06: владение правилом больше не угадывается подстрокой. `guard_rule_pref` сравнивает поля
  точно, поэтому `lookup 101` не равен `lookup 1010`, а `from 1.2.3.4` — не `from 1.2.3.40`;
  консольное правило опознаётся по одной паре констант (`CRULE`, `CTBL`), а не по случайному
  совпадению токенов в строке. Нечитаемая `ip rule show` = DEGRADED без пересадки правил
  (раньше выглядело как «правил нет» и watchdog добавлял свои поверх таблицы владельца).
  `console_rule_present`/`console_default_ok` отдают 0/1/2, ветки off/on обрабатывают 2 как
  unknown и ничего не меняют.
- P01: консольная таблица больше не остаётся с WAN-default при упавшем туннеле. Если
  `default dev Console` поставить нельзя, таблица закрывается `default unreachable`, conntrack
  клиента сбрасывается, запуск отвечает FAIL/DEGRADED (rc 1) словами «трафик отклоняется, а не
  уходит через WAN». Закрытие не липкое: следующий прогон с живым tun возвращает default на
  туннель. Чужие правила и маршруты не трогаются.
- I05: `--adopt-config` стал настоящим шагом. Новый `assets/geomask-mihomo-adopt.py` аддитивно
  (по тексту, с сохранением комментариев) вставляет только то, что нужно geomask: маркер,
  `proxy-providers.sub`, группы `VPN-noP2P`/`AI`, слушатели `ai-devices`/`torrent-direct`;
  tun/dns/secret/rules/proxies владельца остаются байт-в-байт. Кандидат пишется в отдельный
  файл, проверяется `mihomo -t`, и только потом заменяет живой конфиг. Отказ (не mapping, нет
  прокси/провайдеров, уже есть `sub` или одноимённые группы, чужой `listeners`-тип, другой
  proxy у нашего слушателя) называется до первой записи и ничего не меняет.
- N04: владение конфигом — трёхзначный вердикт (0 наш, 1 чужой, 2 не определить). Отсутствие
  PyYAML или битый файл больше не выглядят как «чужой конфиг», на который предлагался
  `--replace-config`. Единая проверка `_mihomo_guard` используется step3, `write_mihomo_config`
  и reinstall, поэтому четыре копии сообщения не разъедутся; preflight сообщает unknown
  отдельно от «не задана подписка».
- I11: сужение selection снимает runtime снятых модулей по данным каталога
  (`owned_resources`): файлы, сервисы (stop+disable реальным init-скриптом), cron-строки под
  общим локом, наша nft-таблица. `geomask_uninstall` использует тот же помощник для `guard` и
  `ai_dns` — раньше hotplug-хук, cron и nft-таблица оставались после «удаления». Состояние и
  конфиги владельца не входят в `owned_resources` и остаются.
- Отдельно всплыло и исправлено: помощники, печатающие список для shell, отдавали CRLF под
  Windows-Python, `read` приносил `\r` в пути и `[ -e ]` молча не срабатывал — теперь вывод
  переводится в LF и CR снимается в цикле.
- Доказательства: `test_guard_entrypoint` 13 → 20 → 22 (RED на старом guard: нечитаемая
  таблица пересаживала правила, `lookup 1010` удовлетворял LAN-правилу, таблица оставалась на
  WAN-default), новый `test_adopt_config` 13, `test_install_safety` 41 → 44 → 46 → 48 (RED:
  adopt «проходил» и ничего не делал; «не читается» показывалось как чужой конфиг; снятый
  модуль сохранял файлы и cron). Стенд: живые netns (P01), `mihomo -t` на реальном бинарнике,
  фактический egress — остаются OPEN.

- Полный gate на этом хосте: `tests/testgate.py run --timeout 4200` — 91 модуль, 1319 тестов
  (1290 выполнено, 29 allowlisted skip), 0 fail, 0 timeout, verdict PASS. Дефолтные 600 с на
  модуль для этой машины малы: `test_reinstall_phase2b` (44 теста симуляции переустановки)
  идёт 2181 с, `test_sandbox_guard` — 580 с; таймаут поднят ключом `--timeout`, сами тесты не
  ослаблены. Единственный сбой первого прогона (`test_routes_ownership`, WinError 32/5 в
  очистке временного каталога) оказался гонкой очистки на Windows и исправлен
  `ignore_cleanup_errors=True` (d9d4449), после чего прогон зелёный.

## Партия 6 — короткие секреты, IPv6 по интерфейсам, бюджет трассы домена (C10/P07, C06/P06, B-020)

- Коммиты: `ce45ff1` (redactor), `c0eb516` (IPv6), `2422295` (трасса домена).
- C10/P07: `api_key`, `access_token`, `client_secret` и их camelCase-формы с короткими
  значениями больше не проходят в YAML/JSON/лог. Ключ нормализуется по компонентам
  (camelCase делится, разделители унифицируются), секретом считается хвостовой
  token/secret/password или известная пара (api+key, access+token, client+secret…).
  `public_key` намеренно остаётся видимым.
- C06/P06: `ipv6.state` хранит значения по интерфейсам (`ifv|<iface>|<key>|<value>`), `off`
  выключает каждый интерфейс с `ip6assign`, `on` восстанавливает по имени. Исчезнувший
  интерфейс не пересоздаётся — сообщается и пропускается. Старый блок `lan` сохранён для
  старых записей и статуса панели.
- B-020: у живой трассы один дедлайн 15 с (`GM_DOMAIN_TRACE_BUDGET`); `http_probe` считает
  `-m`/`--connect-timeout` от остатка и при исчерпании возвращает `kind=deadline` не запуская
  curl; `related_hosts` ограничивает загрузку страницы и пропускает запрос сертификата.
  Ответ несёт `partial`, `probe_path`, `budget_s` и пишет в своих строках, что проба идёт
  с роутера и что результат частичный. Показ в панели и браузерная приёмка — стенд.
- Доказательства: `test_diag_redact` 32 → 37 (RED на старом коде по всем пяти),
  `test_ipv6_state` 3 → 5 (RED по переименованной LAN-секции), `test_doctor` 61 → 64.
  Build/RPC/каталог зелёные.

## Партия 4 — установка: топология, зависимости, честность шагов (I01, I02, I06, I07, I09, I10, I12)

- Коммиты: `2296e3f` (I01/I02), `23371a5` (I06/I09/I12), `bd2a250` (I10), `f9b1a99` (I07).
- I01: step 7 требует VPN-noP2P и AI (их создаёт шаблон); отсутствие VPN — документированная
  одно-туннельная топология, а не ошибка. VPN, объявленный в конфиге, но отсутствующий в API
  контроллера, остаётся ошибкой.
- I02: `geo-backend.sh` перешёл из модуля `luci` в `core`: это единственный writer сетевого
  состояния (IPv6, устройства, маршруты), а headless `core,path_vpn` обязан выключать IPv6.
- I06: `prompt_url` печатает вопрос в stderr, значение — только в stdout (тест на три сценария).
- I07: `normalize_modules` замыкает зависимости из метаданных (ai_dns → path_ai →
  admission_service); тест сверяет shell-рёбра с `modules/*.json` и падает при расхождении.
- I09 (часть): `save_stream` пишет во временный файл с уникальным именем (`mktemp`), а не в
  общий `.zmnew`, и проверяет размер опубликованных байтов вместо доверия `mv`.
- I10: повреждённый `/etc/geomask/modules.json` — отказ (`rc=2`) до первой записи, а не
  «выбрано всё»; sync не перезаписывает повреждённый файл; запись атомарная; интерпретатор
  определяется (python3, иначе python).
- I12: `step5_apply` возвращает ошибку при сбое записи, сида, ассетов списков или состояния
  модулей (`_step5_apply_result`).
- Доказательства: `tests/test_install_safety.py` 29 → 41; sandbox-сценарий S25 переведён на
  новый контракт транзакции; build/RPC/манифест зелёные.
- Осталось: I05 (adopt), I08 (step2 check doctor), I11 (full→subset cleanup), N04 — и стенд.

## Партия 3 — cron: лок обязателен, сравнение внутри лока (I03, I04)

- Коммит: `f8f8c56`.
- I03: `cron_ensure` при отказе лока возвращает 1 и не пишет; три места (sync, legacy
  nodescan, миграция ytwatch) и uninstall проверяют результат `_cron_begin` и не трогают
  crontab без лока.
- I04: `_rs_restore_cron` берёт лок до чтения, сравнивает чужие строки и пишет под ним же;
  отказ лока — незавершённый откат, а не перезапись.
- Помощники cron сделаны реентерабельными (счётчик вложенности; ядровый лок отвечает 3 на
  повторный захват), потому что uninstall/restore законно работают с уже взятым локом.
- Доказательства: `tests/test_install_safety.py` 26 → 29; RED: строка добавлялась/удалялась
  при отказе лока, restore читал до лока.
- Осталось: живой crontab на OpenWrt (BusyBox crond, `lock`-семантика), параллельный
  panel nodes_set во время restore — стенд.

  реальный rpcd) остаются невыполненными: они требуют изолированного Linux/OpenWrt и
  отдельного согласия владельца. Рабочий роутер и `Z:` в этой работе не использовались.

## Состояние ветки

`master` впереди `origin/master` на 22 коммитов; незакоммиченным остаётся только
раздел «ранний этап 0» в плане (добавлен владельцем до начала работ — не трогать).
