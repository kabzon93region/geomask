# v1.9.0 — папка бэкапов в сети (SMB) + ссылки в панели

## Сделано

- **SMB-шар `geomask-backups`**: geomask (шаг geo) идемпотентно добавляет в **уже работающий
  на роутере ksmbd** шар `geomask-backups` → `/root/geomask-backups`, гостевой **только на
  чтение** (существующий шар `configs` = корень на запись остаётся зоной ответственности
  владельца). Перезапуск ksmbd — только при реальном изменении конфига, с проверкой
  `ksmbd.conf` сразу после.
- **Постоянное хранение + ротация «самая свежая»**: `ensure_backup` возвращён на overlay
  (`/root/geomask-backups/`), но архив строится в `/tmp` и затем переносится — старые копии
  на момент сборки отсутствуют, **вложение бэкапов друг в друга (дефект v1.6–1.8) исключено
  конструкцией**. Перед обновлением runner пишет туда же (тоже через /tmp + mv).
  Полная история — на ПК (`fetch_backup.ps1`, glob теперь сначала смотрит /root).
- **Панель**: новый rpcd-метод `backups` (папка, UNC `\\<ip>\geomask-backups`, smb://-URL,
  файлы с размером/датой, признак наличия шара) + блок **«Резервные копии»** в карточке
  «Обновления»: кнопки «Копировать (Windows)» / «Копировать (smb://)» / «Копировать путь к
  файлу» (execCommand-фолбэк — LuCI работает по http, clipboard API без https не отдаёт).
  На «Готово» обновления список перечитывается, свежий бэкап виден сразу. Прямой click-through
  из браузера в проводник не открывается политиками — путь копируется в один клик (Win+R).
- Шаги self-update в консоли теперь содержат финальный UNC-путь бэкапа.

## Безопасность (осознанный компромисс)

Архив sysupgrade содержит ключи WireGuard/URLs подписок; гостевой шар доступен всем в LAN —
ровно как существующий `configs` (и то, и другое — решение владельца, «SMB, что уже есть»).
При желании закрывается в LuCI → ksmbd (guest_ok=no + пользователь ksmbd.adduser).
