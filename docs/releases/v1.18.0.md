# geomask v1.18.0 — три именованных слота и ночной аудит запрещённой подписки

## Зачем

Подписка с запретом на торренты отключена провайдером и, по словам владельца, вернётся утром.
Прежде чем её включать, нужно знать **что именно туда пойдёт**. Раньше это можно было только
угадать: буфер системного журнала на роутере живёт ~4 минуты, а трафик в мёртвую группу почти не
генерирует записей. Плюс в панели было два маршрута («VPN» и «AI»), и подписки нельзя было
расставить по трём полосам, которые появились в v1.17.0.

## 1. Три слота назначения вместо двух

| Слот | Группа mihomo | Провайдер | Что туда идёт |
|---|---|---|---|
| `VPN-noP2P` | `VPN-noP2P` | `sub` | только **доменные** правила MagiTrickle (`mtrickle`) + STUN |
| `VPN` | `VPN` | `sub2` | **все IP-правила** (`mtrickle_bulk`), пины зависших googlevideo-рёбер, ответы входящим пирам |
| `AI` | `AI` | `de5` | `RULE-SET,ai` |

Прежняя группа `RESERVE` переименована в `VPN`, прежняя `VPN` — в `VPN-noP2P`: имя теперь говорит,
что с подпиской можно делать, а не то, что она «запасная». В карточке подписок — три кнопки
`→ VPN-noP2P`, `→ VPN`, `→ AI`; бейдж показывает, чем подписка занята. Назначение в слот `VPN`
создаёт полосу, если её ещё нет (провайдер + группа + перенос IP-правил), с копией конфига и
откатом при провале `mihomo -t`.

Смысл разделения не изменился: **на путь `VPN-noP2P` не попадает ни одно правило по IP**, поэтому
торрент-пир — а это всегда голый адрес — туда маршрутизироваться не может.

## 2. Аудит запрещённой полосы: `geomask-vpnwatch.sh`

```
geomask-vpnwatch.sh --tick     cron раз в минуту: дописывает новые события
geomask-vpnwatch.sh --report   сводка: куда и сколько шло, доля «похоже на P2P»
geomask-vpnwatch.sh --clear    очистить журнал
```

Собирает два источника: решения прокси из системного журнала (строки `dial <группа>` и
`using <группа>`, дедупликация по хэшу) и список открытых соединений из API mihomo (цепочка
начинается с наблюдаемой группы; новые `id` пишутся с источником, портом и байтами). Только
чтение — маршрутизацию скрипт не меняет и не может сломать.

Журнал — `/root/geomask-vpn-audit.log` (не в `/tmp`, чтобы не потерять за ночь), ротация по
`max_lines`. Наблюдаемая группа задаётся в `/etc/geomask/vpnwatch.conf` (`group=VPN-noP2P`).

`--report` отдельно считает **долю адресов-чисел среди целей** — это и есть признак P2P: если
утром там будут голые IP, полосу включать нельзя.

## Установка

```sh
curl -fL -m 60 -o /tmp/geomask.sh 'https://cdn.jsdelivr.net/gh/kabzon93region/geomask@v1.18.0/geomask.sh' && sh /tmp/geomask.sh
```

Существующий `config.yaml` не перезаписывается: переименование групп на живом роутере делается
одноразовой миграцией, а не установщиком.
