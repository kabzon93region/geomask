# geomask v1.17.0 — три полосы: IP-правила больше физически не могут попасть в запрещённую подписку

## Задача, поставленная владельцем

1. Google+AI — **только** через AI-подписку, никаких исключений.
2. Торренты — **никогда** через обычную VPN-подписку (напрямую, через запрет или через другую
   подписку — можно). Причина: провайдер VPN-New увидел BitTorrent в туннеле и отключил подписку.

## Ключевая идея

Пытаться распознать торрент по трафику нельзя (подтвердил и провайдер: клиенты шифруются и ходят на
случайные порты). Поэтому классификация перевёрнута: **на путь запрещённой подписки не должно
попадать ни одно правило по IP**. Торрент-пир — это всегда голый адрес, а значит совпасть с
доменным правилом он не может в принципе. Инвариант проверяется машиной, а не вниманием человека.

## Что сделано

**1. Синк разделяет mtrickle по типу правила** (`assets/sync_mtrickle_mihomo.sh`):

| Файл | Содержимое | Куда ведёт правило |
|---|---|---|
| `mtrickle.yaml` | только домены (на роутере — 1469) | `RULE-SET,mtrickle,VPN` (VPN-New) |
| `mtrickle_bulk.yaml` | только IP-CIDR (1300: Ovh 622, Cloudfront 243, Digitalocean 180, Meta 117, Hetzner 84, …) | `RULE-SET,mtrickle_bulk,RESERVE` |

Разделение по **типу**, а не по имени группы — так оно не ломается, когда кто-то добавит подсеть в
обычную доменную группу.

**2. Третья полоса `RESERVE`** — старая подписка, где P2P не запрещён. Туда же переведены пины
зависших YouTube-рёбер: `- RULE-SET,ytvpn,RESERVE` (раньше они шли в мёртвый VPN).

**3. Слушатель `torrent-direct`**: при наличии полосы `RESERVE` он работает **по правилам** — тогда
AI-домен, попавший в торрент-клиент, всё равно уйдёт в AI (цель №1), а пир — в RESERVE (цель №2).
Без полосы шаблон и `geomask-torrent.sh` выдают фиксированную `proxy: DIRECT`, потому что без
полосы правилный слушатель и был причиной блокировки.

**4. Проверки в `--check`:**

```
lane invariant: mtrickle.yaml has no IP rules
lane: IP ruleset -> RESERVE
lane: youtube edge pins -> RESERVE
listener (torrent-direct:7894, rule-based + RESERVE lane): present
```

Если в `mtrickle.yaml` снова появится IP-правило — это `bad` и ненулевой код возврата, а не
предупреждение.

## Проверено на живом роутере

```
RESERVE: 35 узлов, now=🇦 Албания-1 · Reality
[TCP] 192.168.0.245 --> 188.165.77.110:56627  match RuleSet(mtrickle_bulk) using RESERVE[🇦🇱 Албания-1]
[TCP] ... --> openrouter.ai:443               using AI[🇺 USA 6 VLESS TCP]      → 200
[TCP] ... --> 1337.abcvg.info:80              match RuleSet(torrentdirect) DIRECT → 200
[TCP] ... --> example.com:80                  match Match using GLOBAL[DIRECT]
mtrickle.yaml IP-CIDR: 0   mtrickle_bulk.yaml: 1300   ytvpn.yaml: 6 -> RESERVE
```

Попутно выяснилось, что подписка ставит в список узел «↔️ Автовыбор» на `balancer.vlessi.cloud`,
который **не резолвится нигде** (NXDOMAIN и через 1.1.1.1, и через 8.8.8.8). В `url-test` он
выигрывал выбор и чернотил весь трафик, поэтому провайдер `sub2` получил
`exclude-filter: 'Автовыбор'`.

## Обновление

```sh
curl -fL -m 60 -o /tmp/geomask.sh 'https://cdn.jsdelivr.net/gh/kabzon93region/geomask@v1.17.0/geomask.sh' && sh /tmp/geomask.sh
```

Существующий `config.yaml` установщик не перезаписывает, так что настроенные полосы переживают
обновление. Для новой машины полоса настраивается добавлением третьей подписки и правилом
`RULE-SET,mtrickle_bulk,RESERVE`.
