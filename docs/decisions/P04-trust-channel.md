# P04 — trust/channel/release gate

Статус: **закрыто документацией** (18.11.2026). Новые подписи и ключи не вводятся:
по плану это отдельное решение владельца, а не побочный эффект аудита. Ниже — что реально
есть в коде на момент закрытия и где границы доверия.

## 1. Два независимых канала обновлений

| Канал | Источник | Что проверяется | Код |
|---|---|---|---|
| Self-update | GitHub **releases** (`api.github.com/repos/<repo>/releases/latest`, ассет `geomask.sh` по тегу) | версия в скачанном файле == тег **и** sha256 файла == digest ассета из API; перед этим — `release.py verify` | `src/backend/050-subscriptions.sh.part:206`, `src/backend/060-updates.sh.part:5-10,97-117` |
| Module update | `raw.githubusercontent.com/<repo>/<ref>/...`, по умолчанию `kabzon93region/geomask@master` | sha256 каждого файла из `modules/index.json` того же `ref`; протокол helper'а (P02) | `src/module-update/001-module-update.py.part:47-50,340-358`, `002-module-update.py.part:154-175` |

Ключевое отличие: self-update привязан к **тегу релиза**, module update — к **ref**
(`master` по умолчанию). `ref` можно переопределить в `/etc/geomask/module-update.json`
(`repo`, `ref`), не меняя код.

## 2. Что доказывает целостность, а что нет

Проверяется:

- sha256 скачанного файла против `sha256` в каталоге — до записи на диск
  (`002-module-update.py.part:168-175`); несовпадение = отказ, файл не пишется;
- каталог читается с cache-busting, потому что raw-фронт GitHub отдаёт устаревший
  `modules/index.json` из кэша (`001-module-update.py.part:355-358`);
- пишет только в фиксированный список корней (`INSTALL_ROOTS`), поэтому даже подменённый
  каталог не может направить запись в произвольный путь; модуль, не выбранный владельцем
  (`/etc/geomask/modules.json`), помечается `not-selected` и не обновляется
  (`001-module-update.py.part:24-26,61-76`);
- helper и вызывающий сверяют версию протокола (P02) до любого изменения;
- self-update: версия в скачанном скрипте должна совпасть с тегом, а sha256 файла — с
  digest ассета из releases API; при любом расхождении установка не начинается
  (`src/backend/060-updates.sh.part:106-117`).

**Не** проверяется (и это надо знать, а не прятать):

- подпись каталога и файлов отсутствует: `sha256` лежит в том же канале, что и файлы,
  поэтому сторона, контролирующая репозиторий/аккаунт (или TLS-терминацию на пути),
  может отдать согласованную пару «каталог + файл»;
- нет freshness/anti-rollback: старый, но валидный по sha256 каталог принимается;
- `master` — рабочий канал: WIP-пуш попадает в него сразу и становится доступен
  `mod update` без релиза/тега (P04 именно об этом);
- TLS защищает от пассивного MITM, но не от компрометации GitHub-аккаунта или
  доверенного прокси.

## 3. Release gate (как выпускается то, что видят роутеры)

`tools/release.py publish` (`tools/release.py:188-227`) выполняет по порядку:

1. `check_build.py --verify-only` — сборка обязана совпадать с исходниками;
2. `testgate` — per-module counts/skips/timeouts, немутирующая проверка
   (`tools/release.py:145-170`);
3. git-тег версии, GitHub release с ассетом `geomask.sh`, заметки со ссылкой на гейт;
4. скачивание ассета и сравнение digest с локальной сборкой (`asset_digest`).

`release.py verify [--full]` скачивает ассет, проверяет размер/sha256/`sh -n`/
`--list-modules`; `--full` — установку в одноразовом окружении. `release.py status|drift`
показывают расхождение HEAD и последнего релиза.

Итого: **релизный** канал защищён гейтом и тегом, **модульный** — только sha256 внутри
канала. Это осознанная граница: полноценная подпись требует ключей и процедуры владельца.

## 4. Операционные правила (что считается безопасной практикой)

- Перед `mod update` — свежий полный бэкап и `mod check`: обновление идёт только по
  подтверждённому списку изменений.
- Для «замороженных» роутеров — `ref` на тег релиза, а не `master`; это делается в
  `/etc/geomask/module-update.json` без изменения кода.
- Self-update — только из releases; `release.py drift` должен быть чистым перед публикацией.
- Не считать `sha256` подписью: он доказывает целостность доставки, не авторство.

## 5. Решение и что осталось владельцу

Решение P04 (закрыто): задокументированы trust domain, каналы и release gate; новых
подписей/ключей не назначено.

Остаётся решением владельца (не блокирует текущую готовность, но меняет модель угроз):

1. Ввести подпись каталога (например, отдельный ключ подписи `modules/index.json`) —
   потребует хранения публичного ключа на роутере и процедуры ротации.
2. Перевести module update по умолчанию на тег релиза вместо `master` (одна строка
   конфигурации, но меняет скорость доставки исправлений).
3. Публиковать ли helper `geomask-module-update.py` в каталоге с хешем (сейчас исключён
   намеренно, см. execution log, партия 15).

До решения владельца поведение не меняется: каналы, проверки и отказы остаются такими,
как описано выше.
