# AI-устройства (весь трафик через AI-подписку)

## Идея

Отдельные устройства (например, телефон для зарубежных сервисов) можно целиком провести через
**AI-подписку**, не затрагивая основной VPN других клиентов. Реализуется вторым экземпляром
`hev-socks5-tunnel` (TUN `AI`) и отдельным слушателем mihomo.

## Как включается

В панели LuCI («Персональные режимы устройств») устройству назначается режим
**«Через AI-подписку (весь трафик)»**. Бэкенд:

1. добавляет запись `IP ai NAME` в `/etc/geo-devices.list`;
2. при первом AI-устройстве поднимает второй инстанс `hev-socks5-tunnel` (TUN `AI`,
   `198.19.0.1`, socks `127.0.0.1:7891`), сетевой интерфейс и firewall-зону `AI`;
3. создаёт `ip rule 20000 from <IP> lookup 101` и таблицу `101 default dev AI`.

## Туннель и слушатель

| Элемент | Значение |
|---|---|
| TUN | `AI` (`198.19.0.1`), MTU `8500` |
| hev-инстанс | `/etc/hev-socks5-tunnel/ai.yml` (`tunnel.name: AI`) |
| socks5 | `127.0.0.1:7891` |
| mihomo listener | `ai-devices` (mixed, `127.0.0.1:7891`, **`proxy: AI`**) |

`proxy: AI` в listener форсирует группу `AI` для всего, что приходит в `7891`; правила `rules:`
для этого пути не применяются.

> Слушатель `ai-devices:7891` входит в конфиг, но активируется при старте mihomo. После первого
> включения режима выполните один раз `sh /etc/init.d/mihomo restart` (≈3 с, краткий обрыв) —
> панель предупредит, пока слушатель не активен.

## IP-маршрутизация

```
device IP ── ip rule 20000 (from IP lookup 101) ──► table 101 ──► dev AI
   ──► hev ai (198.19.0.1) ──► socks 127.0.0.1:7891 ──► mihomo ai-devices (proxy: AI) ──► AI-нода
```

LAN и служебные сети остаются локальными за счёт копии маршрутов `main` в таблице 101.

## STUN / WebRTC

Сайты проверки IP (whatismyipaddress и др.) могут детектировать IP через WebRTC/STUN и показывать
домашний адрес. Решение — направлять STUN через VPN на уровне правил mihomo:

```yaml
rules:
  - AND,((NETWORK,udp),(DST-PORT,3478)),VPN
  - AND,((NETWORK,udp),(DST-PORT,19302)),VPN
```

Это правило действует на пути через основной слушатель (`7890`). Для AI-устройств (путь `7891`)
весь трафик и так форсирован в `AI`, поэтому WebRTC-запросы уходят через AI-ноду.

## Приоритеты и частая ошибка

AI-устройства должны иметь `ip rule` с приоритетом **выше** базы fwmark-правил magitrickle
(динамической!). Используется `20000`. Если правило окажется ниже — помеченный magitrickle трафик
уйдёт в основной туннель, и AI-устройство начнёт «ходить вперемешку» (симптом: сайт показывает
домашний IP). См. [ROUTING.md](ROUTING.md).

## Отключение

В панели смените режим устройства (или удалите) — запись из `/etc/geo-devices.list` удаляется,
`ip rule` для IP снимается, при отсутствии AI-устройств второй туннель можно снять.
