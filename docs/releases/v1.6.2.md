# geomask v1.6.2 — семантический поиск ICMP-правила и CI

**Дата:** 2026-10-19. **Тип:** фикс + инфраструктура. Совместимо: параметры добавления правил
не меняются, чинится только проверка наличия.

## Суть фикса

Проверка «есть ли ICMP-bypass» шла по префиксу приоритета:
`ip rule show | grep -q '19901:'`. Но geomask-guard пересаживает наши правила на `база − 100`
при каждом дрейфе базы fwmark-правил magitrickle — после пересадки ICMP-правило живёт на другом
pref, поиск по `19901:` его не находит, и хотплуг `99-default-vpn-route` при следующем `ifup`
добавлял **безвредный дубль** `iif br-lan ipproto icmp lookup main`.

## Изменения

- `assets/geo-backend.sh` и хотплуг `assets/99-default-vpn-route`: наличие проверяется
  **семантически** — `grep -q 'iif br-lan ipproto icmp lookup main'` (как уже делает guard);
  pref при добавлении по-прежнему начальный дефолт `19901`.
- Тесты: новый сценарий **S11** — ICMP-правило на чужом pref (`20100`) не дублируется при
  прогоне хотплуга; плюс статическая проверка, что pref-поиска `19901:` в сборке больше нет.
- **CI (TD-05/TD-06):** публикуемая часть песочницы в `tests/` (`run_tests.sh` + стабы `bin/`),
  `tools/check_build.py` (сборка из исходников == закоммиченный `geomask.sh`),
  GitHub Actions `.github/workflows/ci.yml`: check_build → `sh -n` → тесты на ubuntu.
- `GM_VERSION` → `1.6.2`, README-бейджи (release + CI).

## Обновление

```sh
curl -fL -m 60 -o /tmp/geomask.sh 'https://cdn.jsdelivr.net/gh/kabzon93region/geomask@master/geomask.sh' && sh /tmp/geomask.sh
```

После обновления: `sh /tmp/geomask.sh --check` → ожидается 7/7; повторные `ifup` не плодят
дубли ICMP-правил (`ip rule show | grep -c 'ipproto icmp'` не растёт).
