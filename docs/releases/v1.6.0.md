# geomask v1.6.0 — устойчивый фикс класса B-001 (nft-исключение + watchdog)

**Дата:** 2026-10-18 · **Тип:** фикс + новый компонент · **Обновление:** `sh /tmp/geomask.sh --reinstall --yes`
(или обычный запуск мастера — шаг sync установит guard).

## Почему

Рецидив B-001 18.10.2026: приоритеты правил geomask `20000/20001/20002` оказались **перекрыты**
блоком fwmark-правил magitrickle `19999…19979`. Выяснилось, что при каждом пересоздании своих
правил (рестарт/синк магитрикле) ядро размещает их **прямо ниже текущего минимума в системе** —
то есть после фикса v1.5.8 (правила на `20000`) база гарантированно встала ниже него. Симптом:
AI-устройства показывали РФ-IP на `2ip.io`/`myip.com` (трафик уходил не в AI-туннель).

**Вывод:** любые фиксированные числовые приоритеты проигрывают динамике magitrickle.

## Что сделано

### 1. geomask-guard (новый компонент)

`/usr/bin/geomask-guard.sh` — три защиты:

- **nft-исключение**: `ip saddr <ai/bypass-device> return comment "geomask-excl"` в **голове**
  `ip mangle PREROUTING` (перед прыжками `MT_*`, ~21 цепочка). Пакеты наших устройств не получают
  метку magitrickle → их маршрутизацию определяет только наше правило `from <ip>`, и положение
  fwmark-правил перестаёт иметь значение. Список устройств берётся из `/etc/geo-devices.list`
  (режимы `ai`/`bypass`); устаревшие исключения удаляются автоматически.
- **watchdog `ip rule`**: проверяет наличие и приоритет `per-device/icmp/aidns` правил относительно
  базы magitrickle (`min fwmark-pref`); при нарушении пересаживает на `(база − 100)`, при
  изменении режима устройства убирает чужое правило (`ai` ↔ `bypass`), сбрасывает conntrack.
- **страховка таблицы 101**: `default dev AI` восстанавливается, если пропал.

Компоненты: сам скрипт, hotplug `/etc/hotplug.d/iface/99-geomask-guard` (запуск при `ifup`),
cron `*/5 * * * * /usr/bin/geomask-guard.sh`. Лог: `logread | grep geomask-guard`
(тих, когда всё в порядке — только события).

### 2. Приоритеты 20000 → 19900

`per-device 19900`, `ICMP 19901`, `AI-DNS 19902` — стартовый дефолт ниже текущей базы
magitrickle (`19979`); дальнейший порядок держит watchdog. Обновлены `geo-backend.sh`,
hotplug `99-default-vpn-route`, `AIDNS_RULE_PREF`.

### 3. Проверки и прочее

- шаг sync (`--check`) контролирует установку guard: скрипт, hotplug, cron;
- verify больше не ищет ICMP-правило по устаревшему приоритету `32666` — по семантике
  (`iif br-lan ipproto icmp`);
- деплой на роутер: `--check` → `pass=7/7`, маршруты с меткой magitrickle → `dev AI table 101`.

### Песочница

- стаб `crontab` пишет состояние атомарно (tmp+mv): устранена гонка «`cat >` обрезает файл раньше,
  чем параллельный `crontab -l` его прочитал» — из-за неё терялись cron-записи в тестах;
- фикстуры guard-скрипта/hotplug добавлены; **38/38** тестов.

## Проверка после обновления

```sh
sh /tmp/geomask.sh --check                     # pass=7 fail=0
ip route get 8.8.8.8 from 192.168.0.125 iif br-lan mark 0x4d616769   # dev AI table 101
nft list chain ip mangle PREROUTING | head -8  # geomask-excl перед MT_*
logread | grep geomask-guard
```

С браузера AI-устройства: `2ip.io` / `myip.com` / `whatismyipaddress.com` — все показывают страну
AI-ноды (новая вкладка/инкогнито после сброса conntrack).

## Известные ограничения

- Требуется существующий прогон шага sync (шаг мастера или `--reinstall`) — одновременного
  удаления guard нет (вывод из эксплуатации вручную: удалить скрипт, hotplug, cron-строку).
- Порядок `ip rule` по-прежнему может съезжать при пересоздании правил magitrickle —
  это нормально: watchdog возвращает его ≤5 минут, а на маршруты ai/bypass-устройств
  положение правил магитрикле не влияет (nft-исключение).
