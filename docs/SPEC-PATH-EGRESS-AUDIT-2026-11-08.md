# Раздельный аудит выхода VPN / VPN-noP2P / AI

**Дата:** 08.11.2026, MSK. **Статус:** владелец подтвердил первую поставку — независимые настройки и честные report-only проверки; безопасное применение отложено. Первая report-only реализация установлена точечным пакетом 08.11 около 13:45; отдельные live RPC jobs всех трёх путей проверены. Рабочие маршруты/фильтры не менялись; Apply отложен. Инструкция — [NODE-AUDIT](NODE-AUDIT.md), доказательства — [live summary](../../audit/2026-11-08/node-audit/live-summary.json). Географию Google проверять по ответу самого Google, аналогично service-specific подходу ChatGPT; HTTP-доступность не заменяет геодоказательство.

## Запрос и подтверждённые решения

Владелец запросил независимые разрешённые страны и отдельные проверки трёх путей в LuCI. В уточнениях выбран режим **проверка отдельно, применение отдельно** и ограничение **страны выхода к проверяемому сайту**, а не страны входного сервера. Это не разрешение удалить локальные hosts-записи или менять базовую сеть.

Главный архитектурный документ — [основной план v2](PLAN-2026-11-06-geomask-v2-rework.md). Эта задача — ограниченный вертикальный результат, а не объявление всех этапов v2 завершёнными.

## Пользовательское поведение

- Во вкладке «Ночной аудит узлов подписки» три карточки: VPN, VPN-noP2P, AI. У каждой собственные разрешённые страны, фактически связанная подписка, сохранённая/применённая ревизия, отдельная кнопка проверки и результаты узлов.
- Предлагаемые начальные страны взяты из утверждённого основного плана: VPN NL,DE,FR,SE; VPN-noP2P DE,PL; AI US. До явного сохранения/применения это предложения, не незаметная миграция текущих фильтров.
- «Сохранить» сохраняет желаемый фильтр, не применяет его в mihomo и не меняет соседние пути. Сохранение автономно: PC receipt не требуется (уточнение владельца 08.11 вечером). Полный проверенный бэкап на ПК делает агент перед вмешательством/внедрением; это не runtime-зависимость geomask. No-op не пишет состояние.
- «Проверить этот путь» проверяет узлы только связанного источника/источников в изолированном экземпляре mihomo. Рабочая группа, выбранный узел, production DNS/конфиги и маршруты не переключаются. Скачивание/временное тестовое состояние не выдаётся за read-only отсутствие любых файловых операций: тестовый тракт заранее развёртывается управляемо с бэкапом.
- Отдельная кнопка «Применить результат» показывает preview и причины исключения. Она доступна только для свежего результата той же ревизии/подписки/узлов, при подтверждённом бэкапе и исправном безопасном тракте применения. Если предусловий нет, возвращается конкретная блокирующая причина, а не фиктивный успех.
- Ночной аудит получает самостоятельные результаты трёх путей; частичный провал не скрывается успешной проверкой другой подписки. Автоприменение новой политики не включается скрыто.

## Что именно доказываем

Для VPN/VPN-noP2P явно указываем контрольный сайт и его trace-результат (например, Cloudflare ip/loc/colo). Это наблюдение выхода к этому сайту, не обещание одинакового маршрута всех назначений. Страна/ASN входного сервера остаются отдельной справкой и legacy-ограничением; MSK Bridge не объявляется неправильным только по российскому входу.

Для AI сохраняются раздельные обязательные доказательства Google и ChatGPT, а также остальных сервисов согласованного реестра. Узел не допускается по одному Cloudflare или одному ChatGPT. HTTP 204/200 Google подтверждает только доступность. Если достоверный геопризнак конкретного сервиса пока не поддержан, его страна **UNKNOWN**, совокупный допуск не пройден, применение такого узла как проверенного запрещено. Нельзя подставить country из IP-checker в результат Google.

Диагностика отображает DNS/hosts-переопределения отдельно: local-resolved и remote-resolved запросы могут выходить в разных странах. Нельзя исключить весь исправный узел как «FI» без объяснения, что фактически проверялся сторонний destination из локального hosts. По результатам 08.11 normal local DNS для ChatGPT направляет на 45.155.204.190; его исправление — отдельное решение, не побочный эффект нового фильтра.

## Интеграция и владение

- Стабильные IDs `vpn`, `vpn_nop2p`, `ai`; точные группы VPN, VPN-noP2P, AI; связь с провайдером определяется из фактического `use`, не из имён sub/de5/slot.
- Один узкий canonical store `/etc/geomask/node-audit.json`: schema, generation, path countries, proof requirements. Не записывать те же поля в nodes.conf и в незавершённый policies.yaml параллельно. Legacy nodes.conf сохраняет расписание/старые ограничения; широкие policy-прототипы не активируются этой задачей.
- Один модуль ассета `geomask-node-audit.py` владеет схемой, потеребезопасной обработкой legacy-настроек, отчётами, resolver/probe и exact-group candidate. Встраивается существующим build.py и installer; нет отдельной загружаемой платформы плагинов.
- RPC добавляются только через tools/geo-rpc.json и существующий генератор: nodes_paths_get, nodes_path_save(path_id,countries,expected_revision), nodes_path_check(path_id), nodes_path_apply(path_id,report_revision). Результаты сериализуются настоящим JSON-кодером; входы валидируются до потери типов/NUL при shell-конверсии.
- Перепроверка источника при завершении job и перед apply обязательна. Старый результат не затирает новую настройку. Параллельные задания разных путей не делят временные файлы/результаты.

## Безопасность применения

Новый JSON-owned resource и общий mihomo-конфиг — разные области транзакции. По уточнению владельца обязательный PC backup/offload относится к действиям агента перед внедрением, а не к пользовательскому сохранению настроек. Автономный Save желаемых стран не требует receipt, не перезапускает сервисы и не меняет трафик. Условия будущего live Apply рассматриваются отдельно; оно не реализовано. Секреты не попадают в отчёты.

Применение mihomo нельзя открыть при конкурирующих writers, не соблюдающих общий протокол. Нужен resource-specific lock/revision для installer, panel slot writes, scanner/ai-guard, lane/torrent и reload из sync. Минимальная интеграция допустима без переписывания всего core, но ни один writer данного ресурса не получает обход. Пока gate не реализован/проверен, Apply BLOCKED.

Кандидат изменяет только scanner-owned ограничения выбранной группы, сохраняет соседние группы/подписки/пользовательские правила. Нужны проверка реального кандидата `mihomo -f ... -t`, изолированный runtime trial всех портов/ресурсов, готовый независимый rollback, атомарная установка и проверка runtime/соседних путей. Пустой допустимый пул и UNKNOWN не превращаются в очистку ограничений или DIRECT/fallback. Если безопасная блокировка по основному плану ещё не реализована, такой кандидат не применяется и UI сообщает об ограничении; это не доказательство действующего fail-closed.

P12 исправляется в реальном старом setter: сохраняются ai_guard=0/1, custom/unknown/path-поля и комментарии. Передача частичных новых полей через усечённый старый setter запрещена. Работа с cron не объявляется атомарной без координации всех его writers.

## Проверяемые результаты

1. Два пути на одной подписке с разными странами дают разные результаты и не меняют соседний путь.
2. Все jobs/сохранения/применения имеют scope+revision; malformed/null/controls/NUL/неизвестный path отвергаются до записи.
3. Отсутствующий/битый store не сбрасывается в allow-all; stale source, пустой/невалидный provider, timeout/401/ошибка парсера — ERROR/UNKNOWN, не PASS.
4. Проверки повторяют контроль local-DNS vs remote-DNS при необходимости, включают TLS verification и не вращают production AI-группу.
5. Положительный ChatGPT и UNKNOWN/отрицательный Google исключают общий AI-допуск, и наоборот. Для неподдержанного геопризнака честно показывается UNKNOWN.
6. P12 проверяется реальным обработчиком, не только pure helper; старые настройки и ai_guard=0/1 не теряются.
7. Save работает без receipt/ПК/внешних команд, но только с валидными значениями и актуальной ревизией; stale/ошибка atomic replace не портят предыдущее состояние. Бэкап перед агентским внедрением подтверждён на ПК; Apply остаётся вне первой поставки.
8. Синтаксис, unit, RPC parity, build parity и sandbox проверяются в изолированной копии. Успех старого baseline не считается свежим результатом.
9. Живой rollout — только после локальной приёмки и свежего бэкапа; отдельная проверка реально отданных UI/RPC. Коммит/push/release не делать без запроса.

## Границы готовности

Текущий запрос **не разрешает** молча убрать hosts-переопределения, поменять WAN/network, выбрать другую подписку, ослабить AI/US или включить непроверенный default-deny для всех устройств. Неполные service proofs и безопасный Apply отражаются как незавершённые, а не маскируются наличием кнопок. Приложение не считается готовым, пока реальное сохранение/проверка/применение выбранного scope не прошли приёмку; известные ограничения выносятся владельцу отдельно.
