# geomask v1.14.2 — карточка обновлений больше не врёт про установленную версию

## Проблема

Панель показывала «geomask (ядро) 1.13.5 / Админка LuCI 1.13.5 / geomask-guard 1.13.5»,
хотя на роутере уже был развёрнут 1.14.1. Причина: `_upd_check_now` при попадании в TTL-кэш
(1 час) отдавал файл `check.json` **как есть**, а в нём записаны и версии установленных
компонентов. Кэш переживает переустановку — поэтому после деплоя/отката карточка до часа
показывала устаревшие «установлено», и это выглядело как «обновление не применилось».

## Исправление

- Новый хелпер `_upd_local_block <версия>`: считает `core/panel/guard/backend` и `need` **по факту
  с диска** (файлы компонентов на роутере).
- Ветка «кэш попал» теперь подменяет в кэшированном JSON блоки `"local"` и `"need"` живыми
  значениями; с GitHub кэшируется только `latest` (тег/дайдджест/дата) — это и должно жить в TTL.
- «Свежая» ветка переведена на тот же хелпер — логика больше не дублируется в двух местах.

Побочный, но важный эффект: если компоненты разъехались по версиям (например, установщик
дописал бэкенд, но панель не обновилась), `need` теперь становится `true` сразу, а не через час.

## Тесты

версии, хелпер используется в обеих ветках. Песочница: 140 проверок, юнит-тесты: 16.

## Обновление

```sh
curl -fL -m 60 -o /tmp/geomask.sh 'https://cdn.jsdelivr.net/gh/kabzon93region/geomask@v1.14.2/geomask.sh' && sh /tmp/geomask.sh
```

После обновления достаточно просто перезагрузить страницу панели — принудительно чистить кэш
проверки больше не нужно.
