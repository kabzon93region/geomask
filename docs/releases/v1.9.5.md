# v1.9.5 — SMB-шар бэкапов: force user + аутентифицированный доступ (Windows)

Финальные две причины, почему шар не открывался (проверено боевым циклом на роутере):

1. **Путь под /root**: гостевые сессии ksmbd работают от непривилегированного uid и не
   проходят `drwxr-x--- /root` → ядро молча не поднимало шар (`NT_STATUS_BAD_NETWORK_NAME`,
   при этом соседние /tmp и /www работали). Лечится `force user/group = root` — в LuCI-ksmbd
   это опция `force_root`; ensure_smb_share теперь выставляет `force_root=1`.
2. **Windows блокирует гостевые подключения по политике** (пакеты не уходят с машины вообще;
   `AllowInsecureGuestAuth` + перезапуск LanmanWorkstation не помогли локально) — поэтому
   добавлен **обычный пользователь SMB `geomask`**: пароль генерируется один раз
   (`/root/.geomask-smb.pass`, 0600, переиспользуется), вносится через `ksmbd.adduser`.
   Гость остаётся разрешённым для других клиентов (телефоны), `valid users` не ставится.
3. Панель: блок «Резервные копии» показывает `geomask / <pass>` и кнопку
   «Копировать net use» (готовая команда `net use \\<ip>\geomask-backups /user:geomask ... /persistent:yes`);
   строка backup в консоли обновления тоже ссылается на пользователя.

Проверено E2E с этого ПК: authenticated mapping → листинг, побайтовое чтение md5 = md5
роутера, запись отклонена (read only). Проверяющие тесты S13 дополнены (69 проверок).
