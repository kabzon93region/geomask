## 3. Классификация падений (52)

### A. Изоляция состояния — 19 падений, дефект тестов

Все ошибки одного вида: тест вызывает продуктовый код, тот пишет аудит в дефолтный
`/etc/geomask/node-audit/state`, CI-процесс не root:

```
FileNotFoundError: '/etc/geomask/node-audit/state'
PermissionError: [Errno 13] Permission denied: '/etc/geomask'
  assets/geomask-audit-state.py:223 in locked -> append_event:426
```

Затронуты: `test_migration` (4/4), `test_scheduler` (5/12), `test_node_audit_lifecycle`
(5/9), `test_reapply_chain` (2/6), `test_node_audit` (1/30), `test_apply_guards` (1/16),
`test_scheduler_apply_chain` (1/3).

Причина: `GM_AUDIT_STATE` не выставлен в тесте; на Windows дефолтный путь либо создаётся,
либо подменяется песочницей гейта, поэтому там зелено. Продуктовый код ведёт себя
корректно: при недоступном каталоге он падает fail-closed, а не пишет в другое место.

Фикс (тесты): общий helper, который на каждый тест выставляет `GM_AUDIT_STATE`,
`HOME`, `TMPDIR`, `TEMP` в `<case>/…` и чистит после. Acceptance: перечисленные модули
зелёные на Ubuntu без root.

### B. `test_module_update` — 17 падений, требует разбора

```
module_update.UpdateError: write failed (PermissionError); originals restored
  assets/geomask-module-update.py:819 install_staged
  tests/test_module_update.py:439
PermissionError: .../test-logs/tmp/test_module_update/tmpXXXX/bin/tool.sh
```

Падает и успешный сценарий установки, и `test_checksum_mismatch_writes_nothing`
(там после отказа ожидаются старые байты). Похоже на расхождение в правах/режимах при
стейджинге во временный каталог: Windows-фикстуры выставляют режим, который на Linux
не даёт писать/заменять файл, либо продукт ожидает root для `chmod`. Нужен прогон под
Linux с `strace`/`-v` по одному тесту. Это единственная группа, где нельзя исключить
дефект продукта (запись в целевой каталог).

### C. `test_console_tx` — 7 падений, дефект окружения теста

```
{"ok":false,"error":"console patcher not installed (/usr/lib/geomask/geomask-console.py)"}
  tests/test_console_tx.py:255,301,363
```

Тест ожидает транзакцию консольного патчера, но продукт ищет его по установленному пути
`/usr/lib/geomask/…`, которого в CI-чекауте нет. На Windows путь, видимо, резолвится в
репозиторий. Фикс: тест обязан передавать путь к `assets/geomask-console.py` через env
(тот же приём, что для остальных ассетов) либо продукт должен искать sibling `assets/`
относительно своего файла. Второй вариант — продуктовое улучшение, требует решения.

### D. Семантика блокировок — 4 падения, платформенное расхождение

```
test_lock_protocol: 'RC=0' not found in 'RC=1 INODE=8280988'      (release after SIGKILL)
test_lock_protocol: 'lock order violation' not found in 'R1=0 R2=4 R3=3'
test_console_lock: 'a killed holder kept the lane locked'
test_backend_safety: 'the kill switch kept the lock' (console.lock exists)
```

Ожидания написаны под Git-Bash/Windows: освобождение flock после убийства держателя,
текст ошибки при нарушении порядка, удаление lock-файла при `console off`. На Linux
поведение ядра иное (flock снимается, но helper возвращает 1; сообщение не печатается).
Нужно либо привести helper к единому контракту, либо разделить ожидания по платформам
с явной причиной. Продуктовая логика на роутере проверена живыми прогонами.

### E. Симлинки и pin-swap — 2 падения, платформенное расхождение

```
test_reinstall_phase2e: 'RESTORE_RC=1' при symlinked /etc/mihomo
test_reinstall_phase2f: 'SAFE=1' not found in 'SNAP_RC=0 SAFE=0 VERIFY=0'
```

На Linux симлинк настоящий, на Windows — копия; тесты писались под Windows-поведение.
`phase2e` проверяет поддержку симлинка — на Linux это как раз штатный случай, значит
либо продукт не следует симлинку при restore, либо тест создаёт симлинк не так.
`phase2f` — детект подмены pin без exec: на Linux снапшот считается безопасным.
Оба требуют ручного разбора; возможен реальный дефект restore-пути на симлинках.

### F. `test_sandbox_guard` — 1 падение, каскад

```
Lists differ: [] != ['test_backend_safety.py did not pass rc=1 (FAILED (failures=3))']
```

Guard проверяет, что каждый модуль пишет только в свою песочницу; он же требует, чтобы
модули проходили. Пока группа B/C красная, guard падает автоматически. Отдельного фикса
не требует, перепроверить после A–E.

### G. `test_diag_redact` — 1 unknown-skip, дефект политики гейта

```
unknown: test_batch_accepts_msys_style_paths_on_windows: windows-only path translation
```

Сам модуль прошёл (40 тестов, rc=0), но причина skip `windows-only` отсутствует в
`allowed skip reasons`, поэтому гейт считает unknown-skip и помечает модуль failed.
Фикс: добавить `windows-only` в allowlist (рядом с `windows-acl`) или переименовать
причину. Это же объясняет, почему в списке «failed modules» 16, а падений 52.

## 5. Что исключено

- **Таймауты**: `timeout: 0`; самый долгий модуль `test_reinstall_phase2b` — 298 с при
  лимите 600 с.
- **Регрессия релиза**: CI был красным до сегодняшних правок; Windows-гейт на том же
  коммите зелёный; живой роутер работает.
- **Нехватка Python-пакетов**: PyYAML установлен, остальные импорты проходят.
- **Отсутствие файлов репозитория**: все модули стартуют, ошибок импорта нет.

## 6. Предлагаемый план (партии)

| Партия | Содержание | Модули | Критерий |
|---|---|---|---|
| B1 | Hermetic-окружение в тестах (`GM_AUDIT_STATE`, `HOME`, `TMPDIR`) | A: 7 модулей | зелёные на Ubuntu без root |
| B2 | Путь к ассетам через env вместо `/usr/lib/geomask` | C: test_console_tx | зелёный |
| B3 | Разбор прав/режимов при staged install | B: test_module_update | зелёный или доказан дефект продукта |
| B4 | Контракт блокировок, разделение по платформам | D: lock_protocol, console_lock, backend_safety | зелёные |
| B5 | Симлинки/pin-swap (возможен фикс продукта) | E: phase2e, phase2f | зелёные |
| B6 | Allowlist skip-причин | G: diag_redact | unknown-skip = 0 |
| B7 | Перепроверка sandbox_guard и полный Linux-гейт | F | verdict PASS |

Правила: каждый фикс — отдельный коммит с RED→GREEN, тесты не трогают `/etc`, `/tmp`,
`~`; продуктовый код меняется только при доказанном дефекте; Windows-гейт и живой роутер
остаются зелёными после каждой партии.

## 7. Воспроизведение

```bash
# Linux/WSL, из корня репозитория
python -m pip install pyyaml
python -B tests/testgate.py run --tests-dir tests --log-dir /tmp/gate-linux --timeout 600
bash tests/run_tests.sh

# артефакт текущего CI-прогона
gh run download 44652597472 -n unit-gate-logs -D /tmp/ci-logs
```

Артефакт содержит `summary.txt`, `summary.json`, `progress.txt` и `<module>.log` с
`GM_GATE_JSON:` — по нему можно вытащить точный traceback без повторного прогона.
