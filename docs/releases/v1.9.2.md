# v1.9.2 — порядок очистки бэкапов + корректные значения uci

Два дефекта v1.9.0/1.9.1, вскрывшихся боевым деплоем на роутере:

1. **Вложение не ушло**: и `ensure_backup`, и runner удаляли старые копии **после** запуска
   `sysupgrade -b` — а архиватор в момент запуска сканирует `/root`, где лежала предыдущая
   копия → новый бэкап включил её (9.5 → 19 → 28.5 МБ, замерено 27.10). Теперь purge старых
   копий (`/root/geomask-backups/*` и legacy `/tmp/router-backup-*`) выполняется **до**
   создания; при падении создания на роутера не остаётся копии — вызывающий шаг прерывается,
   история на ПК (`fetch_backup.ps1`).
2. **ksmbd-шар с битыми флагами**: `uci set read_only='1'` сохранил значение **с кавычками**
   (uci не снимает их), mountd выдал `read only = '1'`. Пишем `yes/no` (как у существующих
   шаров) + нормализация уже созданных секций при следующем прогоне шага geo.

Тесты S13 дополнены: yes/no без кавычек, purge-before-create. 66 проверок.
