# geomask v1.14.0 — YouTube: битые рёбра googlevideo уходят в VPN сами

## Проблема

Google раздаёт адреса видео-рёбер (`rrN---sn-XXXX.googlevideo.com`) динамически, и часть из них
блокируется по IP. Статический список имён всегда отстаёт: вчера рабочий хост сегодня недоступен,
и наоборот. При этом весь остальной YouTube (страница, картинки `ytimg`/`ggpht`, API) через запрет
(DPI) работает нормально — на VPN нужны только реально падающие рёбра.

## Как работает watchdog `geomask-ytwatch.sh`

1. **Источник сигнала — собственные ошибки mihomo.** Когда ребро блокируется по IP, ядро пишет
   в лог `dial DIRECT (match RuleSet(ytdirect)) … rrN---sn-XXXX.googlevideo.com:443 error: … i/o timeout`.
   Watchdog разбирает `logread` за последние `window_min` минут и считает повторы по хостам.
2. **Пин по порогу.** Хост попадает в VPN после `fail_threshold` (по умолчанию 2) ошибок — разовые
   сбои не закрепляются.
3. **Единственный источник истины — MagiTrickle.** Хост добавляется правилом `domain` в группу
   **«GoogleVideo VPN»** через API (`:8080`), синк перегенерирует `ytvpn.yaml`, а правило
   `RULE-SET,ytvpn,VPN` стоит **до** `ytdirect,DIRECT`. Никаких ручных ruleset-файлов.
4. **Ночной сброс.** Cron `20 4 * * * … --reset` отпускает именно автоматические пины (список
   хранится в состоянии), возвращая рёбра на zapret. Вручную добавленные в группу правила не трогаются.
5. **Потолок.** `max_pins` (40) — если сыпется всё, watchdog останавливается и пишет в журнал,
   вместо того чтобы молча перевесь весь YouTube на VPN.

## Режимы

| Режим | Поведение |
|---|---|
| `auto` (по умолчанию) | googlevideo идёт напрямую через запрет; в VPN только пиннутые рёбра |
| `blanket` | весь `googlevideo.com` в VPN (поведение v1.13.x) — аварийный вариант |

Переключение: панель geomask → вкладка «Списки и синк» → карточка «YouTube: рёбра googlevideo»
(или `geomask-ytwatch.sh --mode auto|blanket`, `--reset`, `--status`).

## Настройки

`/etc/geomask-ytwatch.conf`: `mode`, `fail_threshold`, `window_min`, `max_pins`, `group_name`.
Устанавливается один раз; при обновлениях geomask существующий файл сохраняется.

## Ограничение (важно знать)

Автоматически ловятся отказы **на уровне установки соединения** (таймаут/refused) — это и есть
IP-блокировка рёбер. Если DPI режет уже после TCP (TLS-рукопожатие висит, а mihomo считает
соединение успешным), ошибки в логе нет и watchdog такой хост не увидит: его можно запинить
вручную, добавив домен в группу «GoogleVideo VPN» в :8080.
