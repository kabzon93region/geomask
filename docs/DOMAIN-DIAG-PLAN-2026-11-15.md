# План: таймаут «Маршрута домена» и несовпадение путей live-проб (B-020)

**Дата наблюдений:** 2026-11-15 · **Статус:** OPEN, отдельная задача после локальных исправлений R01–R12 ([план R01–R12](<RECHECK-PLAN-2026-11-15.md>)). Незавершённые платформенные gates R01–R12 этим условием не объявляются пройденными.

**Происхождение:** внешний BUGLIST B-020 и исторические измерения владельца. Полные локальные логи не входят в Git; этот документ содержит только несекретные сводные результаты. В текущем аудите 18.11 обращения к роутерам запрещены и измерения не повторялись.

Файлы реализации: [doctor](<../assets/geomask-doctor.py>), [панель](<../assets/geo-sync-page.js>), [backend](<../assets/geo-backend.sh>). До исправления обходной путь: проверять маршрут домена **без** галочки «живая проверка»; исторически этот вариант ответил менее чем за секунду, что не является гарантией для любой конфигурации.

## Симптом

Панель → «Диагностика» → «Маршрут домена» → `lmstudio.ai` с галочкой «живая проверка»: `Error: XHR request timed out`. Домен находился в группе MagiTrickle «To VPN», запрос с ПК завершился HTTP 200 за 1.36 с.

Эти наблюдения **не доказывают блокировку провайдером или сайтом**. Connect timeout допускает и другие причины. Вычисленный policy-route и фактический путь конкретного соединения — разные уровни доказательств.

## Подтверждённое и требующее уточнения

1. **Подтверждено:** наблюдавшийся бюджет live-трассы около 29 с превышал RPC-таймаут 20 с. Панель теряла ответ.
2. **Подтверждено по устройству проб:** собственный запрос роутера не эквивалентен LAN PREROUTING-пути клиента. Его результат нельзя без оговорки выдавать за доступность сайта для клиента.
3. **Не установлено:** конкретная причина connect timeout; гарантированный VPN-egress запроса с ПК; повторяемость на другом домене или другом роутере. Для исправления дедлайна устанавливать это не требуется.
