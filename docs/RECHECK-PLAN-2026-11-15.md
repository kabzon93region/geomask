## R01 — P0: DNS-страж меняет список upstream на scalar

**Файлы:** [страж:132–155](../assets/geomask-dnsguard.sh#L132-L155), [заглушка:50–56](../tests/test_dnsguard.py#L50-L56).

`list_write` вызывает `uci set "dhcp.@dnsmasq[0].server=$1"`. Это UCI **string**, а не list. В libuci `uci_alloc_option` создаёт `UCI_TYPE_STRING`; список создаётся другим API. OpenWrt dnsmasq читает `server` через `config_list_foreach`, которому нужны `server_LENGTH` и `server_ITEMn`. Строковый option их не создаёт. Поэтому после apply сконфигурированные `--server` исчезают; с `noresolv=1` возможна полная потеря DNS, без него — незапланированный переход на WAN/ISP resolver. Revert использует тот же ошибочный writer и тип не восстанавливает.

В тесте `uci set` искусственно разбивается на элементы списка, поэтому 14 зелёных тестов не проверяют настоящий контракт. Прежнее утверждение «одна атомарная операция UCI set безопасно заменяет список» неверно и отзывается.

**Исправление и приёмка:**
- [x] Сначала красный тест с сохранением UCI-типа string/list, а не только значений.
- [x] Кандидат UCI в отдельном конфигурационном каталоге; создавать настоящие list entries, сохранять тип/порядок/scoped zones и отсутствие option.
- [x] Проверять получившуюся конфигурацию dnsmasq ДО изменения live; ошибка на любой стадии возвращает original bytes и тип.
- [ ] На отдельном OpenWrt-стенде проверить generated `server=`/`no-resolv`, отказ DoH, восстановление, кэш, bootstrap, AI-зоны. Не использовать рабочий роутер.

**Статус R01 — закрыт локально, коммиты `acbcdec` + `56da4b5`.** Настоящий `uci`-стаб (`tests/uci_stub.py`) моделирует libuci: `set` на списке даёт `UCI_TYPE_STRING`, `add_list` превращает строку в список, `get` печатает список через пробел, `export` даёт `option`/`list`, дельты лежат в `<savedir>/<pkg>`. ## R12 — P1: ошибка replace/delete теряет ownership оставшегося маршрута

**Файл:** [route sync:226–247](../assets/geomask-routes.sh#L226-L247).

- [x] Ownership обновлять по реально оставшимся собственным entries; при ошибке не терять запись старого маршрута.
- [x] Повторный sync после снятия отказа должен исправлять таблицу без ручного удаления owned-файлов и без удаления чужих записей.

Остаточный риск (задокументирован): байт-идентичное чужое или отличающееся только декорациями; Linux-only — реальная нормализация iproute2, коды отказа, BusyBox `ip`/`awk`, атомарность `mv`, SIGKILL между мутацией и записью.

**Read-only разбор (17.11.2026, `audit-temp/r12-analysis-20261117/`, `probe_r12.py` + `probe-r12-results.txt`; дерево с незакоммиченным R05).** Механика подтверждена: `geomask_routes_sync:236-265` наполняет `_new` только успешными `replace` (:260-261), `:281 cp -f _new owned` затирает файл при любом `_fail`; после этого префикс либо объявляется foreign (replace-отказ: во втором проходе 0 вызовов `replace`, rc 77 навсегда), либо становится «тихим сиротой» (delete-отказ: `_new` его не содержит, removal-loop больше не видит, следующий sync отдаёт rc 0). Пробы: refused replace → owned пуст, таблица держит старый A+LAN, второй проход не ретраит; refused delete → rc 0, 0 `del`, маршрут навсегда; частичный успех → выпавшие префиксы потеряны; refused `cp` → `cp -f` трункует owned (пустой файл при rc 77); foreign на том же префиксе → наш A выпадает из owned, при снятии desired остаётся навсегда вместе с чужим. `owned` — отдельный файл на таблицу (`owned-100/101/102`, :49), сбой 101 не портит 100.

**Алгоритм reconcile (принят):** Phase 1 авторизация по префиксу — `replace` только если occupants пусты или все в `owned`, иначе `_fail=1` и наши старые записи не трогаем; Phase 2 `replace`, успех → `_new` += строка и `_wrote` += префикс, неудача → `_fail=1` без выкидывания; Phase 3 removal-loop как есть; **Phase 4 (новое)**: `ip route show table $_rt > _after`, `owned_new` = строки `_after`, где строка ∈ старый `owned` ИЛИ её префикс ∈ `_wrote` — так упавший replace сохраняет старую запись, упавший delete сохраняет удаляемую, успешный replace берёт фактическую установленную форму, чужое не попадает никогда; запись `awk > owned-<t>.tmp.$$` + `mv -f` в том же каталоге, при неудаче старый owned не трогать и `_fail=1`. Отказ чтения ПОСЛЕ мутаций = 77 (не 76, иначе 76-ретрай повторит мутации); до мутаций = 76 и owned не тронут. Опционально `retry-<t>`: park при 77 ставит маркер, успех/enqueue его чистят, `_gm_route_has_queue` его не считает очередью (иначе hotplug начнёт спавнить worker), `gm_route_drain` раз в прогон конвертирует `retry`→`pending` — иначе на стабильном PPPoE триггера для восстановления может не быть. **77 по-прежнему не ретраится worker'ом** (граница R05). Остаточный риск: байт-идентичный чужой маршрут неотличим; hardening — `proto`-метка и хранение установленной формы, только Linux-стенд. Тесты: refused replace/delete, частичный успех, усечённая запись owned, foreign на том же префиксе, внешнее удаление, отказ `route show` до/после мутаций, изоляция таблиц, отсутствие `*.tmp`. Linux-only: реальные коды отказа `ip`, нормализация вывода ядром (`linkdown`/`expires`/`proto`/`metric`), BusyBox `ip`, атомарность `mv` на overlayfs/tmpfs.
