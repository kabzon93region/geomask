# geomask v1.5.4 — мгновенное применение + корректное удаление устройств

## Исправлено (критично)
- **Удаление устройства больше не оставляет правило маршрутизации.**
  `dev_del` удалял `ip rule ... lookup main`, но у AI-устройства правило
  живёт в `lookup 101` — после удаления устройства оно продолжало ходить
  через AI-туннель. Теперь удаление идёт по таблицам явно:
  `ip rule del from <ip> lookup main` + `lookup 101`.

## Как быстро применяется (замерено на роутере)
- **Добавление устройства в «Персональные режимы»: ~0.6 c** — команда панели
  (`ubus dev_add`) вызывает `_apply_routing` синхронно: правило
  `32611 from <ip> lookup 101` (для режима AI) появляется сразу же, ждать
  5-минутный cron НЕ нужно. Проверено: после добавления
  `ip route get <dst> from <ip> iif br-lan` → `dev AI`.
- **Удаление: ~0.6 c** — правило снимается сразу же.
- Первый в жизни вызов режима AI дополнительно провизионирует туннель
  (hev-ai + зона firewall + drop-in) — это занимает небольшое время **один
  раз**, дальше добавление любой операции ~0.6 c.
- Если при добавлении указан MAC — ещё раз перезапускается dnsmasq
  (резерв адреса), на маршрутизацию не влияет.

## Проверено на роутере
- Добавление/удаление устройства в режимах `ai` и `bypass`: правила
  появляются и исчезают корректно, чужие правила не задеваются.
- Финальный набор правил после тестов = исходный (5 правил для реальных
  устройств), файл устройств чистый, AI-нода работает.
