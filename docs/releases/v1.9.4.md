# v1.9.4 — JSON-экранирование обратных слэшей (починка rpcd-методов)

- `cmd_backups` писал UNC (`\\ip\share`) в JSON без экранирования: последовательности вида
  `\g` невалидны → rpcd не парсил вывод плагина → `ubus call geo-sync backups` возвращал
  **Invalid argument** (прямой CLI-запуск бэкенда «работал», поэтому дефект был виден только
  из панели). Теперь unc/smb идут через `json_esc` (аргументом, не stdin!).
- `say()` раннера self-update: то же — msg с UNC попадал в `status.json` без экранирования →
  после v1.9.1+ обновлений `upd_status` через rpcd ломался. Раннер экранирует `\` и `"`
  sed'ом перед записью status.json (steps.log/geo-sync.log остаются «сырыми» — они
  экранируются на выдаче в cmd_upd_status).
- Тест S13+ на наличие экранирования; функциональная проверка build-then-move и валидного
  JSON — в песочнице (68 проверок).
