# Диагностика: проверки, маршруты домена, логи

Модуль `doctor` и вкладка «Диагностика» в панели. Задача модуля — отвечать на вопросы
«почему сайт идёт туда», «всё ли живо» и «что за страна на выходе» без экспериментов
через ассистента: нажал кнопку — получил текст и лог.

## Где это живёт

| Что | Где |
|---|---|
| Движок | `/usr/lib/geomask/geomask-doctor.py` (Python, без внешних зависимостей) |
| Вкладка | панель «Гео-маскировка и AI» → «Диагностика» |
| RPC | `diag_list`, `diag_run`, `diag_log`, `diag_domain` (объект `geo-sync`) |
| Логи | `/root/geomask-logs/<проверка>.log` |
| Модуль | `doctor`, необязательный (`--modules=core,path_vpn,doctor`) |

Без установленного модуля вкладка не падает: RPC отвечает
`{"ok":false,"error":"модуль doctor не установлен"}`, панель показывает это сообщение.

## Проверки

Три группы, запускаются по одной или все сразу. «Проверить всё» выполняет только
быстрые проверки; живые (с запросом наружу) — отдельной кнопкой.

Сверху вкладки — **вердикт одной строкой**: «всё в порядке» / «всё работает, но N
проверок просят внимания» / «есть проблемы: N — откройте их, в каждой написано, что
делать». У каждой проверки, которая не `ok`, под строкой стоит подсказка
**«что делать»** с точной командой. Логика простая: диагностика показывает и
объясняет, а чинит владелец (или сам, если это безопасно и он попросил).

### Модули

Для каждого модуля каталога (`modules/index.json`) — состояние его файлов по SHA-256:
актуален / есть обновление / изменён локально / неполный / не выбран. Логика берётся
из помощника обновлений (`geomask-module-update.py`), а не дублируется.

### Роутер

- `router_system` — модель, версия OpenWrt, ядро, аптайм;
- `router_resources` — память, свободное место overlay и `/tmp`, load average;
- `router_services` — dnsmasq, mihomo, MagiTrickle, hev, rpcd, syncd;
- `router_netfilter` — таблицы nft (fw4, MagiTrickle), `ip rule` для таблиц 100/101;
- `router_backup` — возраст последнего бэкапа в `/root/geomask-backups`;
- `update_state` — есть ли обновления или неполные модули.

### Сеть

- `net_wan` — интерфейс WAN, адрес, маршрут по умолчанию;
- `net_dns` — разрешение `ya.ru` через 127.0.0.1, блокировка `doubleclick.net`;
- `net_internet` — `generate_204` и время ответа;
- `net_tunnels` — устройства Mihomo/AI/VPN-noP2P/Wireguard, их адреса и MTU.

### Пути

- `path_vpn`, `path_vpn_nop2p`, `path_ai` — группа в mihomo, число узлов, текущий узел
  и страна по имени узла;
- `path_egress` (**живая**) — реальный запрос через каждый доступный слушатель
  (7891 AI, 7894 VPN, 7892 VPN-noP2P) и через путь по умолчанию: какая страна видна
  сайту на самом деле;
- `path_rules` — обязательные правила (`RULE-SET,mtrickle`, `ytvpn`), наличие
  ruleset-файлов, `mihomo -t`.

## Маршрут домена

Вкладка «Маршрут домена»: вводится домен, выводится весь путь — от DNS до DPI.

```
Домен: live.wardogs.bulkhead.pragmaengine.com

DNS:                   → 52.209.166.76, 52.208.110.223
MagiTrickle:           группа «wardogs» (интерфейс pppoe-wan), правило namespace:live.wardogs...
Правило mihomo:        не участвует — MagiTrickle уводит трафик в pppoe-wan мимо mihomo
Выход:                 напрямую через pppoe-wan — так решил MagiTrickle (страна Россия, RU)
Запрет (DPI):          в hostlist строкой «live.wardogs...» — DPI обходится (nfqws 572 571, режим autohostlist)
Проверка HTTP:         HTTP 404 за 0.33 с, адрес 52.209.166.76 (с роутера)
Связанные хосты:       не найдено (страница не отдала ссылок)

Итог: напрямую через pppoe-wan — так решил MagiTrickle (страна Россия, RU)
```

Что означает каждый шаг:

1. **DNS** — что вернул резолвер роутера. `0.0.0.0` = домен заблокирован adblock.
2. **MagiTrickle** — группа, в которую домен попал, и её интерфейс. «Домена нет ни в
   одной группе» — пойдёт по общим правилам mihomo.
3. **Правило mihomo** — первое совпавшее правило в порядке конфига, с номером строки и
   политикой (VPN / VPN-noP2P / AI / DIRECT / REJECT / GLOBAL). Для `RULE-SET`
   показывается, какая именно строка списка совпала. Если группа MagiTrickle привязана к
   физическому интерфейсу (`pppoe-wan` и т.п.), написано «не участвует»: пакет уходит в
   WAN мимо mihomo, и его правила тут ни при чём.
4. **Источник правила** — откуда взялся `RULE-SET`: `mtrickle.yaml` пересобирается из групп
   MagiTrickle, поэтому домен вписан один раз, а не два.
5. **Выход** — текущий узел группы и страна по его имени; для DIRECT — «напрямую через
   провайдера, Россия»; для прямого интерфейса — «напрямую через pppoe-wan, так решил
   MagiTrickle».
6. **Запрет (DPI)** — участвует ли zapret: `nfqws` запущен, домен найден в
   `/opt/zapret/ipset/zapret-hosts-user.txt` (или в autohostlist), либо исключён строкой из
   `zapret-hosts-user-exclude.txt`, либо идёт через туннель и запрет ему не нужен. Если
   домена нет в hostlist — так и написано, с командой, что добавить.
7. **Проверка HTTP** (только с галочкой «живая проверка») — реальный запрос с роутера: код
   ответа и время. `2xx`/`3xx`/`4xx` = сайт ответил (путь верный), `5xx` = ошибка сервера,
   таймаут/TLS-сбой разбираются отдельно.
8. **Связанные хосты** — домены, от которых зависит страница (редиректы, ссылки, формы,
   iframe, SAN сертификата), у каждого свой путь и страна; если расходятся только картинки —
   это помечено как норма.

Правила `AND`/`OR` (например QUIC-REJECT для видео) распознаются по доменным
под-условиям: для `googlevideo.com` маршрут покажет `REJECT`.

## Логи

- У каждой проверки свой файл: `/root/geomask-logs/<id>.log`.
- Каждый запуск дописывает блок `=== <ISO-время> <состояние> ===` и строки деталей.
- Хранятся **7 дней**: при каждой записи блоки старше срока удаляются, а раз в сутки
  cron `geomask-doctor-prune` (04:40) чистит файлы, которые давно не трогали.
- Файл ограничен 200 КБ: старые блоки отрезаются, архив не растёт без предела.
- В панели кнопка «Лог» у каждой проверки показывает хвост файла.

## Из терминала

```sh
python3 /usr/lib/geomask/geomask-doctor.py list          # список проверок + прошлые результаты
python3 /usr/lib/geomask/geomask-doctor.py run all       # все быстрые проверки, JSON
python3 /usr/lib/geomask/geomask-doctor.py run net_dns   # одна проверка
python3 /usr/lib/geomask/geomask-doctor.py domain chat.openai.com
python3 /usr/lib/geomask/geomask-doctor.py domain youtube.com --live
python3 /usr/lib/geomask/geomask-doctor.py log path_ai
python3 /usr/lib/geomask/geomask-doctor.py prune
```

## Как добавить проверку

1. Написать функцию, возвращающую `(state, summary, details)` или
   `(state, summary, details, fix)`; `state` — `ok`/`warn`/`fail`, `fix` — что делать
   (для проверок, где совет зависит от состояния).
2. Зарегистрировать её в `build_registry()`:

```python
register('network', 'net_mtu', 'MTU до провайдера', check_net_mtu, live=True,
         fix='Проверьте MTU туннеля в панели → Настройки')
```

`live=True` — проверка делает запрос наружу и не попадает в «Проверить всё».

## Границы

Движок ничего не меняет в конфигурации: только читает файлы, дёргает `ubus`/`nft`/`ip`
и (по кнопке) делает один HTTP-запрос. Логи — единственное, что он пишет.
