# План: таймаут «Маршрута домена» и неверный путь live-проб (B-020)

**Дата:** 2026-11-15 · **Статус:** план, реализация **после** плана R01–R12 ([R01–R12](RECHECK-PLAN-2026-11-15.md))
**Связь:** [BUGLIST B-020](../../docs/BUGLIST.md) · evidence: `Y:\openwrt\audit-temp\router-diag-20261115\`

Этот план выполняется отдельной сессией **после** завершения плана R01–R12,
чтобы не пересекаться с его правками в тех же файлах (`geomask-doctor.py`,
`geo-sync-page.js`, `geo-backend.sh`). До реализации обходной путь для владельца:
проверять маршрут домена **без** галочки «живая проверка» (отвечает < 1 с).

## Симптом

Панель → «Диагностика» → «Маршрут домена» → `lmstudio.ai` с галочкой «живая проверка»:
`Ошибка: Error: XHR request timed out`. Домен есть в группе MagiTrickle «To VPN»,
сайт с ПК работает (http=200 за 1.36 с).

## Измерения на рабочем роутере (15.11.2026, только чтение)

| Проверка | Результат |
|---|---|
| `ubus call geo-sync diag_domain` без live | **0.85 с**, ok, маршрут верный (To VPN → mtrickle_bulk → VPN → Германия-13) |
| тот же вызов с live (`python3 geomask-doctor.py domain lmstudio.ai --live`) | **28.9 с** |
| live: `http_probe` curl `--connect-timeout 8` до lmstudio.ai | 8.0 с — connect timeout (прямой выход роутера не проходит) |
| live: `related_hosts` curl `--max-time 20` **без** connect-timeout | 20.0 с — полный таймаут |
| `curl --interface pppoe-wan https://lmstudio.ai` | connect timeout (прямой путь закрыт) |
| `curl` с ПК (LAN-клиент → MagiTrickle → mihomo → VPN) | **http=200, 1.36 с** |
| LuCI RPC timeout | `(L.env.rpctimeout ?? 20)*1000` = **20 с** (`/www/luci-static/resources/rpc.js:5`) |
| egress роутера (`ip route get 104.26.7.153`) | через `pppoe-wan`, прямой выход |

## Корневые причины (две)

1. **Live-пробы меряют не тот путь.** Собственный трафик роутера (uid 0) идёт по
   основной таблице через `pppoe-wan` напрямую — метки MagiTrickle ставятся только
   на LAN PREROUTING. Для доменов, которые закрыты на прямом пути (именно поэтому
   они в списке VPN), живая проверка гарантированно получает connect timeout и
   показывает «сайт не отвечает», хотя для клиентов он работает.
2. **Бюджет времени live-трассы (~29 с) превышает XHR-таймаут LuCI (20 с).**
   Вызов обрывается, панель не получает даже частичного результата. У `related_hosts`
   curl вообще нет connect-timeout, у прочих шагов таймауты не агрегируются.

## Задачи

### D1. Live-пробы идут по пути клиента (причина 1)
- Файлы: `assets/geomask-doctor.py` (`http_probe`, `related_hosts`, возможно `resolve`).
- Варианты (выбрать по итогам анализа): проба через mihomo proxy (`mixed-port: 7890`)
  с учётом правил маршрутизации; либо policy-route/fwmark пробного соединения как у
  LAN-клиентов; либо честная маркировка шага «live-проба идёт напрямую с роутера,
  не через VPN-путь клиента» + отказ от слов «сайт не отвечает» в этом режиме.
- Минимум: вывод должен явно говорить, каким путём выполнена проба.

### D2. Общий бюджет трассы ≤ 15 с (причина 2)
- Файлы: `assets/geomask-doctor.py`.
- Общий дедлайн трассы (например 15 с) с распределением по шагам; каждому curl —
  явный `--connect-timeout` (4–5 с) и `--max-time`; при исчерпании бюджета —
  вернуть **частичный** результат с пометкой «не уложились в бюджет», а не падение.
- `related_hosts` — только при остатке бюджета; без полного 20-секундного ожидания.

### D3. Панель не теряет ответ при таймауте
- Файлы: `assets/geo-sync-page.js` (domRun).
- Варианты: per-call таймаут больше 20 с для этого вызова (например `L.env.rpctimeout`
  на время вызова) **или** async job + опрос (по образцу `upd_status`). Предпочтительнее
  D2: синхронный вызов, гарантированно укладывающийся в 20 с.

### D4. Тесты и верификация
- Юнит: бюджет времени (мок curl с таймаутами), частичный результат, egress-выбор
  пробы (мок маршрута: LAN-путь vs прямой), отсутствие «сайт не отвечает» при
  не-том пути.
- На стенде/после установки: `diag_domain lmstudio.ai` с live — ответ < 20 с,
  живая проверка показывает путь клиента; `XHR request timed out` не воспроизводится.
- Не использовать рабочий роутер как стенд изменений; там только read-only проверка.

## Критерии готовности

- «Маршрут домена» с live возвращает результат < 20 с для домена из VPN-списка.
- Вывод live-шага честно указывает путь пробы (клиентский VPN-путь или прямой egress).
- B-020 в BUGLIST получает ссылку на коммит и статус FIXED.
