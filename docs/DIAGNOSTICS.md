# Диагностика: проверки, маршруты домена, логи

Модуль `doctor` и вкладка «Диагностика» в панели. Задача модуля — отвечать на вопросы
«почему сайт идёт туда», «всё ли живо» и «что за страна на выходе» без экспериментов
через ассистента: нажал кнопку — получил текст и лог.

## Где это живёт

| Что | Где |
|---|---|
| Движок | `/usr/lib/geomask/geomask-doctor.py` (Python, без внешних зависимостей) |
| Вкладка | панель «Гео-маскировка и AI» → «Диагностика» |
| RPC | `diag_list`, `diag_run`, `diag_log`, `diag_domain`, `diag_bundle` (объект `geo-sync`); выдача архива — `console_diag_get` |
| Логи | `/root/geomask-logs/<проверка>.log` |
| Модуль | `doctor`, необязательный (`--modules=core,path_vpn,doctor`) |

Без установленного модуля вкладка не падает: RPC отвечает
`{"ok":false,"error":"модуль doctor не установлен"}`, панель показывает это сообщение.

## Проверки

Три группы, запускаются по одной или все сразу. «Проверить всё» выполняет только
быстрые проверки; живые (с запросом наружу) — отдельной кнопкой.

Сверху вкладки — **вердикт одной строкой**: «всё в порядке» / «всё работает, но N
проверок просят внимания» / «есть проблемы: N — откройте их, в каждой написано, что
делать». У каждой проверки, которая не `ok`, под строкой стоит подсказка
**«что делать»** с точной командой. Логика простая: диагностика показывает и
объясняет, а чинит владелец (или сам, если это безопасно и он попросил).

### Модули

Для каждого модуля каталога (`modules/index.json`) — состояние его файлов по SHA-256:
актуален / есть обновление / изменён локально / неполный / не выбран. Логика берётся
из помощника обновлений (`geomask-module-update.py`), а не дублируется.

### Роутер

- `router_system` — модель, версия OpenWrt, ядро, аптайм;
- `router_resources` — память, свободное место overlay и `/tmp`, load average;
- `router_services` — dnsmasq, mihomo, MagiTrickle, hev, rpcd, syncd;
- `router_netfilter` — таблицы nft (fw4, MagiTrickle), `ip rule` для таблиц 100/101;
- `router_backup` — возраст последнего бэкапа в `/root/geomask-backups`;
- `update_state` — есть ли обновления или неполные модули.

### Сеть

- `net_wan` — интерфейс WAN, адрес, маршрут по умолчанию;
- `net_dns` — разрешение `ya.ru` через 127.0.0.1, блокировка `doubleclick.net`;
- `net_internet` — `generate_204` и время ответа;
- `net_tunnels` — устройства Mihomo/AI/VPN-noP2P/Wireguard, их адреса и MTU.

### Пути

- `path_vpn`, `path_vpn_nop2p`, `path_ai` — группа в mihomo, число узлов, текущий узел
  и страна по имени узла;
- `path_egress` (**живая**) — реальный запрос через каждый доступный слушатель
  (7891 AI, 7894 VPN, 7892 VPN-noP2P) и через путь по умолчанию: какая страна видна
  сайту на самом деле;
- `path_rules` — обязательные правила (`RULE-SET,mtrickle`, `ytvpn`), наличие
  ruleset-файлов, `mihomo -t`.

## Маршрут домена

Вкладка «Маршрут домена»: вводится домен, выводится весь путь — от DNS до DPI.

```
Домен: live.wardogs.bulkhead.pragmaengine.com

DNS:                   → 52.209.166.76, 52.208.110.223
MagiTrickle:           группа «wardogs» → напрямую в интернет через pppoe-wan; правило namespace:live.wardogs...
Правило mihomo:        не используется: трафик уходит напрямую в интернет через pppoe-wan, mihomo его не видит
Выход:                 напрямую в интернет через pppoe-wan — так решила группа «wardogs»; страна Россия (RU)
Запрет (DPI):          включён: домен в списке zapret (строка «live.wardogs...») — запрос к сайту маскируется от провайдера (nfqws работает, режим autohostlist)
Проверка HTTP:         HTTP 404 за 0.30 с, адрес 52.209.166.76 — сайт ответил (запрос с роутера)
Связанные хосты:       не найдено — страница не ссылается на другие домены

Итог: zapret (запрос маскируется) → MagiTrickle: группа «wardogs» → pppoe-wan → интернет, мимо mihomo; страна Россия (RU)
```

**Итог — это весь путь, а не только выход.** Слева направо: что обрабатывает запрос, кто
решает направление, куда он уходит и чей это адрес. Для туннельного домена та же строка
выглядит так:

```
Итог: MagiTrickle: группа «To VPN» → mihomo: список mtrickle → туннель VPN → узел «🇳🇱 Нидерланды-16 · Reality · g13»; страна Нидерланды (NL)
```

Если домен попал в правило «любой другой», путь начинается с «группы MagiTrickle нет»: это
значит, что направление выбрала группа `GLOBAL`, а не ваша группа MagiTrickle.

Что означает каждый шаг:

1. **DNS** — что вернул резолвер роутера. `0.0.0.0` = домен заблокирован на роутере
   (adblock или hosts). «Домен не существует» — NXDOMAIN, проверьте написание.
2. **MagiTrickle** — группа, в которую домен попал, и куда она его отправляет: «напрямую в
   интернет через pppoe-wan», «в mihomo (там выбирается узел VPN)», «в AI-туннель».
   «Домена нет ни в одной группе» — сработает общее правило mihomo.
3. **Правило mihomo** — какое правило сработало, человеческими словами: «№47 любой другой
   домен → группа GLOBAL», «№44 список mtrickle → группа VPN — строка «DOMAIN-SUFFIX,...»».
   Если группа MagiTrickle привязана к физическому интерфейсу, написано «не используется:
   трафик уходит напрямую, mihomo его не видит» — пакет до mihomo просто не доходит.
4. **Источник правила** — откуда взялся список: `mtrickle.yaml` собирается из групп
   MagiTrickle, поэтому домен вписан один раз, а не два.
5. **Выход** — что реально происходит с трафиком: «напрямую в интернет через провайдера;
   страна Россия (RU)», «через туннель VPN на узел «…»; страна Нидерланды (NL)»,
   «REJECT — трафик к домену отбрасывается, сайт не откроется».
6. **Запрет (DPI)** — участвует ли zapret и что это значит на практике:
   - `включён: домен в списке zapret — запрос к сайту маскируется от провайдера` (в скобках
     строка списка, режим и то, что `nfqws` работает);
   - `включён: zapret добавил домен сам после нескольких неудачных попыток`;
   - `выключен: домена нет в списке zapret — запрос идёт как есть, провайдер видит сайт`;
   - `выключен: домен (или его зона) «ru» в списке исключений zapret`;
   - `не нужен: трафик идёт через туннель, провайдер видит только зашифрованный канал`;
   - `выключен: служба zapret не запущена`.
7. **Проверка HTTP** (только с галочкой «живая проверка») — реальный запрос с роутера:
   `2xx`/`3xx`/`4xx` = сайт ответил, соединение проходит; `5xx` = ошибка сервера; таймаут,
   сброс и TLS-сбой разбираются отдельно, с подсказкой про узел.
8. **Связанные хосты** — домены, от которых зависит страница (картинки, скрипты, ссылки,
   формы, iframe, SAN сертификата), у каждого свой путь и страна. Если расходятся только
   картинки — это помечено как норма. Если сайт не ответил, шаг пишет «не проверялось» и не
   показывает чужие домены: файл страницы удаляется перед каждым запросом.

Правила `AND`/`OR` (например QUIC-REJECT для видео) распознаются по доменным
под-условиям: для `googlevideo.com` маршрут покажет `REJECT`.

## Логи

- У каждой проверки свой файл: `/root/geomask-logs/<id>.log`.
- Каждый запуск дописывает блок `=== <ISO-время> <состояние> ===` и строки деталей.
- Хранятся **7 дней**: при каждой записи блоки старше срока удаляются, а раз в сутки
  cron `geomask-doctor-prune` (04:40) чистит файлы, которые давно не трогали.
- Файл ограничен 200 КБ: старые блоки отрезаются, архив не растёт без предела.
- В панели кнопка «Лог» у каждой проверки показывает хвост файла.
- Архив диагностики добавляет `diagnostics/<id>.log` для проверок, у которых лог уже есть;
  для этого он читает файлы, а не запускает проверку.

## Из терминала

```sh
python3 /usr/lib/geomask/geomask-doctor.py list          # список проверок + прошлые результаты
python3 /usr/lib/geomask/geomask-doctor.py run all       # все быстрые проверки, JSON
python3 /usr/lib/geomask/geomask-doctor.py run net_dns   # одна проверка
python3 /usr/lib/geomask/geomask-doctor.py domain chat.openai.com
python3 /usr/lib/geomask/geomask-doctor.py domain youtube.com --live
python3 /usr/lib/geomask/geomask-doctor.py log path_ai
python3 /usr/lib/geomask/geomask-doctor.py prune
```

## Как добавить проверку

1. Написать функцию, возвращающую `(state, summary, details)` или
   `(state, summary, details, fix)`; `state` — `ok`/`warn`/`fail`, `fix` — что делать
   (для проверок, где совет зависит от состояния).
2. Зарегистрировать её в `build_registry()`:

```python
register('network', 'net_mtu', 'MTU до провайдера', check_net_mtu, live=True,
         fix='Проверьте MTU туннеля в панели → Настройки')
```

`live=True` — проверка делает запрос наружу и не попадает в «Проверить всё».

## Архив диагностики: что внутри, хранение и выдача

На вкладке «Диагностика» есть **одна** кнопка «Скачать архив диагностики». Она собирает
`diag_bundle`, а полученные байты отдаёт `console_diag_get` — тот же приватный spool и тот
же путь выдачи, что у прежнего архива консоли. **Проверки по нажатию не запускаются:** архив
читает только уже сохранённые состояния и логи (`diag_list` и файлы, на которые он
указывает); сетевые пробы выполняются отдельными кнопками «Проверить» / «Проверить всё».

`console_diag` остался совместимым входом для карточки консоли: он вызывает тот же сборщик и
упаковщик, отличие только в наборе (без per-check логов) и форме ответа (`file` вместо
`name`). Второго экспортёра, второго `tar` и второго пути выдачи нет.

Архив и его паспорт (`<имя>.tar.gz.json`) лежат в приватном каталоге `/tmp/geomask-diag`
(0700, только root); доступ к ним — через помощник `/usr/lib/geomask/geomask-diag-spool.py`,
который открывает файлы по закреплённому дескриптору каталога и не следует символьным
ссылкам.

### Состав

- `diagnostics/index.json` — `generated_at` и `entries` по каждому пункту `diag_list`:
  `id`, `title`, `area`, `state`, `last_state_at`, `log_state`;
- `diagnostics/<id>.log` — сохранённый лог проверки для тех, у кого он есть (хвост в пределах
  общего бюджета; логи Doctor и так ограничены 200 КБ);
- системный набор консоли: `summary.txt`, `ip-rule.txt`, `route-table-<N>.txt`, `tun.txt`,
  `firewall.uci`, `network.uci`, `nft.txt`, `logread.txt`, `console-config.json`,
  `group-CONSOLE.json`, `connections.json`, `config.masked.yaml` (и `conntrack-console.txt`,
  когда есть `timeout`).

### `state` и `log_state`

`state` — последнее известное состояние проверки: `ok`, `warn`, `fail` или `not_run`.
`last_state_at` берётся из заголовка последнего блока `=== <ISO> <state> ===` в сохранённом
логе; если лога нет, используется время последнего общего прогона из кэша Doctor.

`log_state`:

- `included` — лог вошёл в архив;
- `empty` — файл лога существует, но в нём нет записей;
- `not_run` — проверка ещё не запускалась (файла лога нет).

`state: "not_run"` — это и есть «без запуска» в подписи после скачивания: «в архиве: N
проверок, M без запуска».

### Маскирование

Перед упаковкой и системный набор, и каждый `diagnostics/<id>.log` проходят через
`geomask-diag-redact.py` (R02): UCI-секреты, ключи WireGuard/PPPoE, пароли и токены
провайдеров, `Authorization`, URL с учётными данными, YAML-секреты mihomo и секреты в
JSON-ответах заменяются. Последний гейт — `verify`: если в архиве всё-таки находится похожее
на секрет, архив не создаётся и не регистрируется. Маскирование — фильтр по шаблонам, а не
гарантия «в архиве нет ничего чувствительного»: перед передачей архива третьим лицам
проверьте его содержимое.

### Срок и уборка

Уборка — один проход `retain` при каждой сборке; порядок фаз фиксирован:

1. **возраст** по `mtime`: архив и его паспорт удаляются вместе, старше
   `GM_CONSOLE_DIAG_KEEP` часов (по умолчанию 24, клампится 1…720);
2. **осиротевшие паспорта** (`*.json` без архива) — старше 5 минут;
3. **временные файлы** `.sidecar-*` и `.part-*` — старше 1 часа;
4. **каталоги сборки** `geomask-console-diag.XXXXXX` от прерванных экспортов — старше
   2 часов (и в spool, и в `TMPDIR`);
5. **количество** архивов, затем 6. **суммарные байты**.

Учитываются только имена `geomask-console-diag-*.tar.gz` и их паспорта; посторонние
файлы (`router-backup-*.tar.gz`, `notes.txt`) не считаются и не удаляются. Уборка не
хеширует архивы — только `lstat` и разбор маленьких паспортов.

### Квоты

Две независимые квоты: spool — это tmpfs (RAM), шара — overlay (persistent), поэтому
мусор из RAM не вытесняет постоянные копии и наоборот.

| Переменная | По умолчанию | Кламп | Что ограничивает |
|---|---|---|---|
| `GM_CONSOLE_DIAG_KEEP` | 24 | 1…720 ч | срок жизни архива и копии в шаре |
| `GM_CONSOLE_DIAG_QUOTA` | 8 МиБ | 2…64 МиБ | сумма байт в spool |
| `GM_CONSOLE_DIAG_FILES` | 4 | 1…32 | число архивов в spool |
| `GM_CONSOLE_DIAG_SHARE_QUOTA` | 6 МиБ | 2…64 МиБ | сумма байт в папке бэкапов |
| `GM_CONSOLE_DIAG_SHARE_FILES` | 3 | 1…16 | число копий в папке бэкапов |

При достижении квоты вытесняется **самый старый** зарегистрированный архив (по времени
регистрации), а не отказывает новый экспорт: иначе диагностика заклинила бы именно на
больном роутере. Только что созданный архив и архивы моложе 2 минут не вытесняются;
если новый архив всё равно не помещается, он удаляется, и панель получает отказ
«архив N байт не помещается в квоту M». Учёт и вытеснение идут под `flock(2)` на
дескрипторе каталога, поэтому два параллельных экспорта не могут оба увидеть «место
есть». Квота проверяется один раз — при регистрации; предпроверок до сбора нет.

### Копия в шаре

Копия в `/root/geomask-backups` появляется только при включённой шаре (маркер
`/etc/geomask/backup-share.enable`) и делается атомарно: `.part-<hex>` → `fsync` →
`rename`, права 0600, `mtime` как у бандла (срок в шаре и в RPC совпадает). Сбой
(нет места, права, каталог 0777) не оставляет половины файла: в ответе `shared:false` и
`share_note` с причиной (`no-space`, `perm`, `mode`, `missing`, `disabled`). Уборка шары
выполняется до и после копии и **не зависит от маркера**: снятый opt-in не оставляет
вчерашние копии на overlay. `router-backup-*` не трогается никогда.

### Целостность и границы продюсеров

После `tar` архив принимается только после полного чтения оглавления (`tar -tzf`):
частичная запись, которую BusyBox может завершить с кодом 0, не регистрируется и не
попадает в шару. Вывод продюсеров ограничен на входе: `ip`/`uci` — 2000 строк,
`nft` — 4000 строк, `logread` — хвост 400 строк без строк длиннее 2048 байт,
`conntrack` — 5 секунд и 2000 строк (без утилиты `timeout` файл не создаётся, причина
пишется в `summary.txt`). JSON-ответы больше 512 КиБ (группа — 64 КиБ) заменяются
валидным `{"error":"response too large","bytes":N}`, конфиг mihomo больше 512 КиБ —
строкой `error: config too large`; каталог сборки больше 1,5 МиБ отклоняется до
`verify`/`tar` с перечислением трёх крупнейших файлов.

Логи проверок ограничены отдельно: на все вместе — 384 КиБ (настраивается
`GM_DIAG_BUNDLE_LOG_TOTAL`), на один лог — не больше 64 КиБ, и не меньше 8 КиБ на проверку;
читается хвост файла. Если каталог сборки всё равно перерос 1,5 МиБ, архив отклоняется с
перечислением крупнейших файлов, а не собирается и не выбрасывается после `tar`.

### Скачивание

`diag_bundle` возвращает `ok`, `name`, `bytes` и счётчики `checks`/`not_run` — имя
зарегистрированного архива, без base64 и без пути. Панель передаёт это имя в
`console_diag_get`; имя не приходит из URL и не является путём. `get` отдаёт самый свежий
**валидный** зарегистрированный архив: паспорт без архива (файл удалили вручную)
пропускается, а не ломает кнопку; для явного имени с пропавшим архивом ответ «архива нет:
файл удалён». Скачивание ничего не удаляет: сорванная загрузка браузера не должна
уничтожать единственную копию. Срок проверяется по `created` паспорта и совпадает с уборкой.

## Границы

Движок ничего не меняет в конфигурации: только читает файлы, дёргает `ubus`/`nft`/`ip`
и (по кнопке) делает один HTTP-запрос. Логи — единственное, что он пишет.
