## geomask v1.5.0

Критический фикс маршрутизации Wi-Fi-устройств через AI/VPN-подписку.

### Проблема

На устройствах с режимом «всё через AI» (192.168.0.125) выход в интернет шёл
вперемешку: Google по-русски, 2ip.io = Россия, whatsmyip = UK, 2ip.ua = NL.
Туннель AI был исправен.

### Причина

`ip rule` приоритеты: правила групп magitrickle стоят на 32645..32665 (база
растёт вверх с числом групп; раньше была 32673), а наши:
- icmp-bypass на 32666,
- per-device src на 32670/32694.
Любой пакет, чей IP-адрес есть в ipset-е группы (любой домен, резолвшийся через
роутер), помечается в mangle (`xt target MARK`) и первого же fwmark-правила
уходит в таблицу группы (default dev Mihomo) → обычный путь mihomo →
смешанные выходы (DIRECT / VPN-группа) и ping в туннель. Per-device правило
не успевало примениться. Fix in 11.10 был верен на тот момент, но база
уползла вниз с ростом числа групп.

### Исправлено

- ICMP-обход переехал: `32666 → 32610`
- Per-device src-правила (bypass и ai): `32694/32670 → 32611`
- Запас до базы fwmark-правил: ~35 групп.
- Hotplug (и asset) используют те же приоритеты и актуальные комментарии.

### Проверка после применения

- `ip rule show`: icmp 32610 и src 32611 — первыми после local-таблицы, до
  fwmark 32645.
- С .125: 2ip/whatsmyip = Германия; в логе mihomo `using AI[...]`.
- Пинг до google.ru с LAN работает.
- Smoke: сервисы, интернет, DNS (норм/adblock), группы VPN/AI, ubus geo,
  sync-правила, hotplug syntax.

### Установка

```sh
curl -fL -m 60 -o /tmp/geomask.sh 'https://cdn.jsdelivr.net/gh/kabzon93region/geomask@master/geomask.sh' && sh /tmp/geomask.sh
```
