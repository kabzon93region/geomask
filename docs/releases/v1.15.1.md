# geomask v1.15.1 — торрент-слушатель больше не может утопить AI в DIRECT

## Вектор

Слушатель `torrent-direct` в v1.14.4/1.15.0 имел жёсткую политику `proxy: DIRECT`. Это значило:
**всё**, что через него пройдёт, уходит напрямую — включая AI-домены. Достаточно было включить в
qBittorrent «использовать прокси для общей работы» или направить на `192.168.0.1:7894` любое другое
приложение, и политика «Google+ИИ только через USA» ломалась молча. Владелец поставил это первым
критичным требованием, поэтому вектор закрыт.

## Решение

У слушателя убрана политика — он возвращается на обычную цепочку правил:

```yaml
  - name: torrent-direct
    type: mixed
    port: 7894
    listen: 192.168.0.1
    # политики нет намеренно: решает цепочка правил
```

Поведение для торрентов не изменилось (трекер ловит `torrentdirect`, пир — `MATCH,GLOBAL`, и то и
другое DIRECT), но AI-домен через тот же прокси теперь идёт в AI.

Сначала это было проверено на изолированном экземпляре mihomo: слушатель без `proxy:` действительно
возвращается к правилам (`example.com` → 200 по правилу DIRECT, остальное → `dial GRP (match Match/)`).

## Замер на живом роутере через 192.168.0.1:7894

```
openrouter.ai:443     match RuleSet(ai)            using AI[🇺 USA 6 VLESS TCP]   ← не утекло
api.openai.com:443    match RuleSet(ai)            using AI[🇺 USA 6 VLESS TCP]
1337.abcvg.info:80    match RuleSet(torrentdirect) using DIRECT                   ← трекер как надо
211.75.205.187:6969   match Match                  using GLOBAL[DIRECT]          ← пир как надо
```

## Плюс — аудит всей цепочки правил на утечки AI

Проверено, что ни один AI-хост не перехватывается правилами, стоящими **до** `RULE-SET,ai`
(17 правил всего, `ai` на 12-м). Учитывалось не только точное совпадение, но и вложение по
родительским суффиксам — иначе `ytdirect` с `googleapis.com` проглотил бы AI-домены.
Итог: **0 пересечений**; `ai ∩ ytdirect = 0`, `ai ∩ torrentdirect = 0`, `ai ∩ ytvpn = 0`.
Живой лог: все AI-хосты, замеченные в буфере, ушли через политику AI.

В `--check` добавлена защита от регресса: если внутри блока `torrent-direct` появится `proxy:` —
это считается ошибкой (`bad`), а не предупреждением.

## Почему нельзя было проверить проще

`mihomo -t` поле `proxy:` у слушателя **не валидирует**: конфигурация с несуществующей политикой
проходит тест и разваливается только в рантайме. Поэтому все изменения слушателей сопровождаются
рантайм-замером.

## Тесты

S24 дополнен тремя проверками (отсутствие форсированной политики в скрипте и в шаблоне, детект
политики в `--check`). Песочница: **178** проверок, юнит-тесты: 16.
