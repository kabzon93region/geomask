## 1. Назначение документа

Превратить конфигуратор одной конкретной домашней сети в geomask с понятной моделью путей, объяснимой диагностикой и отключаемыми возможностями. При этом не потерять действующие настройки, не ослабить требования маршрутизации и не переписывать всё одновременно.

Это утверждённая дорожная карта и архитектурные границы, а не безусловное разрешение выполнять изменения на роутере. Перед кодированием каждого этапа оформляется его короткая исполнимая спецификация: точные интерфейсы, формат данных, задачи и проверяющие тесты. План целиком не превращается в одну гигантскую задачу.

Документ заменяет прежнюю очередь работ **для этой инициативы**, но не переписывает исторические файлы:
- прежний план v2 от 02.11 и актуализация от 06.11 (удалены 08.11 как заменённые; уникальные открытые вопросы сохранены в сводке проекта);

## 2. Решения владельца от 06.11

| Вопрос | Принято | Практическое следствие |
|---|---|---|
| Поставка модулей | Модули внутри единого релиза | Один проверенный установщик и согласованная версия; без отдельно скачиваемых сторонних плагинов |
| Поддерживаемые установки | Текущий роутер + новые установки с готовым стеком | Проверяем необходимое OpenWrt-окружение и наличие mihomo/MagiTrickle/hev; не устанавливаем прошивку и весь сторонний стек |
| Диагностика | Наблюдение + тест по кнопке | Нет нового периодического мониторинга произвольных сайтов; ручной тест не переключает живую группу |
| Страны обычного VPN | NL, DE, FR, SE | Если FR/SE отсутствуют в подписке, показываем отсутствие; используем только доступные разрешённые страны |
| Страны VPN-noP2P | DE, PL | Отдельная политика этого пути, не копия фильтра VPN |
| Требования AI | US; узел проходит все обязательные сервисные проверки | Google, ChatGPT и остальные сервисы из явного контрольного набора проверяются раздельно; провал/UNKNOWN хотя бы одной проверки исключает весь узел из AI-пула |
| Нет подходящего узла | Соединение по этому пути запрещено; сообщить пользователю | Не расширять список стран, не уходить в DIRECT или в другой путь/подписку автоматически |
| Разрешённый P2P | Только через существующий выделенный P2P-прокси, далее в P2P-разрешённый VPN-путь | Прокси оформляется модулем; весь клиентский P2P, включая пиры/DHT/трекеры, должен быть назначен на него |
| Трафик вне P2P-прокси | P2P, нераспознанное и неразрешённое блокируются | Остальной разрешённый трафик следует выбранному пути устройства; угадывание назначения и скрытая пересылка в другой путь запрещены |

Формулировка владельца: «если нет подходящего, значит нельзя соединяться по этому пути, иначе это нарушает требования соединения… AI… только US».

Не считать ответ разрешением на автоматическую смену подписки. Внутри выбранной подписки автовыбор допустим только среди узлов, удовлетворяющих всем требованиям пути. Ручной выбор подписки тоже не отменяет требования пути.

Переход к новой раскладке стран выполняется **отдельным явным применением после предпросмотра**, а не как побочный эффект миграции формата.

## 3. Сохраняемые ограничения и не-цели

- Правила [AGENTS.md](../../AGENTS.md) обязательны: работать в Y, не читать/писать Z, не трогать базовую сеть без отдельного согласования.
- Любое изменение на роутере — только после свежего полного `sysupgrade -b`, сохранённого на ПК с проверенной суммой; исключение хранения одной копии на роутере остаётся в пределах действующих правил. Нет подтверждённого бэкапа — нет изменяющей операции.
- Единый механизм применения не даёт автоматическим скриптам исключения из backup-предусловия. Если автоматический entry point не может выполнить предусловие, он не получает права изменения; это проверяется до его включения.
- До живого применения mihomo: проверка **кандидата** через `-f`, trial в `/tmp` на других портах, готовый откат; после применения проверка живого состояния. Не обещать сохранность всех соединений при reload.
- Секреты, URL подписок, HWID, ключи, полные конфиги и бэкапы не попадают в публичные тесты, журнал, Git и диагностический экспорт.
- Существующие пользовательские изменения сохраняются. `geomask.sh` генерируется, а не правится вручную. Коммиты, push и релизы — только по отдельному запросу.
- Кнопка самостоятельного выбора AI-подписки сохраняется; исчезновение старого `de5` не является основанием удалить саму возможность.
- Действующий гостевой backup-share не перенастраивается в рамках планирования. Его риск известен; переносимость не означает автоматическое открытие такой шары на новой установке.
- Не делаем магазин плагинов, произвольное исполнение загружаемых модулей, поддержку всех архитектур OpenWrt и автоматическую настройку WAN/PPPoE.
- Нельзя объявить отсутствие P2P на restricted-подписке доказанным только по отсутствию статических subnet-правил или по нулю в журнале. Проверяем конкретные механизмы и честно ограничиваем вывод.

## 4. Модель системы и владение состоянием

### 4.1 Различаем три сущности

- **Подписка** — источник узлов и его свойства, включая заявленную допустимость P2P. Это не географический путь.
- **Путь** — политика назначения: источник узлов, критерии допуска, группа/туннель/слушатель и поведение при отказе. Один источник может обслуживать несколько путей независимо.
- **Модуль** — устанавливаемая в составе релиза возможность со своим жизненным циклом. Количество модулей не определяется количеством подписок.

У путей стабильные идентификаторы, не зависящие от отображаемого имени группы. Политика P2P привязана также к свойствам подписки: нельзя обойти запрет, переименовав группу или назначив ту же подписку другому пути.

### 4.2 Карта компонентов — целевые границы

| ID | Ответственность | Зависит от | Обязательность |
|---|---|---|---|
| `core` | Безопасная запись, backup/rollback, общие результаты операций, RPC/ACL, журнал, проверка зависимостей | — | Всегда |
| `paths` | Подписки, пути, интеграция mihomo/MagiTrickle/hev, защитные ограничения, маршруты/guard | core | Всегда; состав путей настраивается |
| `diagnostics` | Чтение состояния, объяснение пути сайта, ручной изолированный тест | core, paths | Входит в поддерживаемые профили первой версии |
| `node-filter` | Редактор и сканер фильтров по путям, предпросмотр кандидатов | core, paths | Отключаемый; обязательные требования активного пути остаются в paths |
| `ai-dns` | Специализированный DNS-путь AI-устройств | core, paths | Нужен при соответствующем режиме устройства |
| `device-modes` | Режимы устройств и привязка к идентичности, а не только к текущему IP | core, paths; ai-dns для полного ai-режима | Отключаемый с проверкой зависимостей |
| `youtube` | Пины/режимы YouTube и их восстановление | core, paths | Отключаемый |
| `torrent-lane` | Управление торрент-слушателем/списками и относящийся к ним UI | core, paths | Отключаемый; общий запрет P2P для restricted остаётся в paths |
| `backup-share` | Сетевой доступ к архиву | core | Отключаемый; создание бэкапа перед записью не отключается |
| `self-update` | Получение релиза и UI обновления | core | Отключаемый; проверка совместимости и безопасная локальная установка остаются |

`lane` — реализация транспорта пути внутри `paths`, а не вторая независимая модель маршрутизации. Шаблоны списков — обслуживающая возможность `paths`, не отдельная платформенная подсистема первой версии. Новые модули добавлять только при самостоятельной потребности.

Диагностика может читать общие сервисы проверки, но paths не зависит от UI диагностики. Проверки допуска узлов, обязательные для безопасности, принадлежат paths; node-filter предоставляет их настройки/результаты. Циклических зависимостей быть не должно.

### 4.3 Один владелец изменения

- MagiTrickle остаётся хозяином своих групп: менять их через существующий API, не конкурирующей ручной записью YAML.
- `paths` описывает желаемую политику и формирует изменения конфигурации mihomo; persistent-запись и применение идут только через core.
- Сканы, sync, panel, installer, torrent и update не пишут один общий конфиг независимо друг от друга.
- У операции есть generation/revision; устаревший результат скана не может затереть более новую ручную настройку.
- Переход от старых writers к общему механизму постепенный; перед вводом нового конкурирующего изменяющего входа все writers **этого ресурса** должны соблюдать один lock и revision-протокол.
- Нельзя менять ресурс вне своей области владения. Удаление модуля очищает только его явно зарегистрированные артефакты.

## 5. Безопасность допуска и результат операций

### 5.1 Строгое поведение при отказе

Для активного обязательного пути отсутствие подходящего узла означает состояние BLOCKED. Это не повод генерировать запасное MATCH/DIRECT-правило или использовать другую страну.

- UNKNOWN, провал проверки, устаревшее доказательство соответствия и подтверждённое нарушение — разные причины, но ни одна не является разрешением обходить требования.
- Последний конфиг можно сохранить как данные для отката. Продолжать через него передачу можно только пока он сам удовлетворяет текущей политике и имеет действующий допуск.
- Если узел перестал соответствовать политике, закрываются принадлежащие этому пути активные соединения; соседние пути не сбрасываются без необходимости.
- Защита охватывает все входы: основной rule-based listener, fixed-policy listener, прямое назначение интерфейса MagiTrickle, per-device rules, DNS AI-клиента. Один исправленный listener не доказывает защиту остальных входов.
- Запрет должен сохраняться при падении туннеля, рестарте и удалении необязательного модуля, а не только пока жив watchdog. Перекрывающие правила и fallback проверяются отрицательными тестами.

**Граница аварийного запрета и backup-предусловия.** Fail-closed механизм и условия истечения/отзыва допуска заранее устанавливаются как часть управляемого изменения с полным бэкапом на ПК. Прекращение передачи и закрытие принадлежащих сервису соединений должны выполняться самим уже работающим механизмом по применённой политике, без последующей административной правки конфига, UCI/nft/ip rules или рестарта. Недоступность ПК не продлевает допуск. Новая настройка политики, исправление правил или перезапуск всё равно требуют бэкапа: аварийный запрет не является разрешением обходить AGENTS. Если выбранная реализация для запрета вынуждена выполнять такую административную правку, она не удовлетворяет этому контракту; до её выбора нужен пересмотр реализации либо отдельное явное решение владельца об изменении правила. Обязательный тест: допуск истёк или отозван при недоступном ПК, новые и действующие соединения не продолжают запрещённую передачу, административных записей/рестартов не было.

### 5.2 Доказательства AI-выхода

**Решение владельца после рецензии:** проверять не один ChatGPT, а весь обязательный набор сервисов, включая Google и ChatGPT. Допуск узла — логическое AND всех обязательных результатов. Если хотя бы один сервис не подтверждает требования, возвращает ошибку или UNKNOWN, **весь узел** не допускается в AI-пул, а не исключается только одно назначение.

Контрольный набор — явный versioned-реестр сервисов и поддерживаемых проверок. Для Google/OpenAI нельзя молча ставить PASS по ответу постороннего IP-checker. Для каждого теста определяются проверяемое назначение, достоверный признак выхода, ожидаемая страна, таймаут и срок действия результата. Если достоверного способа проверки нет — UNKNOWN с объяснением, не выдуманный успех. Новая обязательная проверка инвалидирует прежний совокупный допуск, пока узел не пройдёт её.

Хранить отдельные результаты с временем, сервисом, идентичностью узла/провайдера и сроком действия; совокупный допуск недействителен, когда недействителен любой обязательный результат. Проверка конечного набора не является математическим доказательством маршрута всех возможных будущих соединений. В UI перечислять реально покрытые сервисы, ограничения метода и время измерения; не подменять «все обязательные проверки прошли» обещанием «проверен каждый пакет». Непроверенные/неразрешённые соединения дополнительно блокируются политикой §5.3.

До реализации этапа 2 его спецификация фиксирует состав начального контрольного набора, достоверные методы, технические таймауты, срок допуска и условия повторной проверки. Google и ChatGPT обязательны; остальные включённые в AI-политику сервисы нельзя считать проверенными без записи в наборе и пригодного теста. Без конечного срока, проверки актуальности и инвалидирования при смене узла/подписки механизм нельзя объявлять обеспечивающим допуск. Численные значения и расписание не считать уже согласованными владельцем.

Проверяющий запрос не должен пропускать пользовательский трафик через ещё не допущенный узел и не переключает живую группу: используется изолированный тестовый тракт. Сам тракт подготавливается при управляемом развёртывании с бэкапом; кнопка диагностики не создаёт новые production-конфиги, маршруты и listener-ы. Если тест требует дополнительного изменения роутера, это отдельная изменяющая операция с preflight, а не замаскированный read-only вызов. Bootstrap/DNS/служебный трафик такого теста должен быть узко ограничен, а не превращён в обход для клиентских приложений.

Разделять ручную диагностику и существующую автоматическую защиту. Выбор «диагностика по кнопке» не отменяет согласованные guard/scan-механизмы. Новые постоянные проверки и их нагрузку нельзя включать незаметно: расписание допуска согласуется до живого развёртывания. Пока допуск недействителен, обязательный путь закрыт.

### 5.3 P2P-прокси и строгий допуск вне него

**Окончательное уточнение владельца:** P2P-прокси уже есть; он оформляется модулем. Вне него блокировать P2P, нераспознанные и неразрешённые соединения. Более раннюю идею автоматического распознавания с пересылкой любого найденного P2P в другой путь не считать выбранной реализацией.

- Выделенный ingress P2P-прокси направляется только в явно выбранный путь, подписка которого допускает P2P и узлы которого удовлетворяют его политике. Нет такого выхода — блокировка, без DIRECT или AI-резерва.
- P2P-ingress не является универсальным обходом обязательной AI/US-политики и иных явных запретов. Известный AI-запрос, ошибочно направленный клиентом в P2P-прокси, отвергается с объяснением, а не получает не-US выход через закреплённый VPN-listener. Доступ к ingress ограничивается поддерживаемыми клиентами/локальной политикой; его границы проверяются отдельно.
- На поддерживаемом клиенте через этот прокси должны идти не только трекеры, но также пиры и поддерживаемые UDP/DHT/µTP-механизмы. Поддержка транспорта проверяется в runtime; неподдерживаемый механизм отключается/блокируется, а не обходится прямым подключением. Не обещать, что произвольный клиент умеет проксировать весь UDP.
- Вне P2P-ingress действует default-deny: только явно разрешённые, идентифицированные и удовлетворяющие политике соединения направляются в выбранный путь устройства. Отсутствие P2P-сигнатуры, известный порт или строка SNI сами по себе не являются доказательством разрешения.
- Правило действует для клиентского WAN-трафика всех управляемых устройств, включая полный ai и bypass. Эти режимы определяют путь **разрешённого** трафика, а не обход допуска. Локальные LAN/management и необходимый control-plane описываются отдельными узкими правилами; не вводить широкое разрешение «весь роутер».
- Классификация/допуск применяются до per-device source-rule и fixed-policy AI-listener либо в другом эквивалентном месте, доказанно охватывающем все входы. Перестановка только rules mihomo не решает обход через source-IP/tunnel. Mark-clear не должен стирать доверенную классификацию P2P-ingress или вновь разрешать запрещённый поток.
- Если зашифрованное/неидентифицированное соединение нельзя отнести к разрешённому классу поддерживаемым методом, его блокируют с причиной; не объявляют обычным трафиком по умолчанию. Известный P2P вне прокси блокируется, а не автоматически перенаправляется.
- Набор разрешённых приложений/назначений для текущих устройств фиксируется до живой миграции. Несовместимость показывается в предпросмотре; никаких скрытых временных allow-all. Возможные отказы игр/звонков/приложений — явное следствие выбранного строгого режима.
- Не обещать универсальное распознавание произвольного туннелированного или намеренно замаскированного P2P. Приёмка относится к поддерживаемым признакам, явным разрешениям и проверенным отрицательным сценариям; обнаруженный обход считается дефектом, не разрешённой best-effort политикой.

Отключение torrent-lane закрывает его ingress, но не снимает запрет P2P/UNKNOWN вне прокси. Полный ai-профиль означает выбранный путь всего **разрешённого не-P2P** трафика, а не безусловное разрешение любого пакета устройства.

### 5.4 Общие результаты

Операции сообщают не только `ok`, но и различают: выполнено и проверено; без изменений; ошибка; не проверено; заблокировано политикой; неприменимо для данного профиля. Это целевые категории, не утверждение о существующем API.

Для запрета показывать: какой путь недоступен, какое требование не выполнено, когда и чем это установлено, что пользователь может сделать без ослабления политики. Сообщение не содержит секретов.

## 7. Обязательная матрица испытаний

| Сценарий | Ожидаемое поведение |
|---|---|
| AI: US отсутствует; есть только FI/RU/пустой ответ | Путь BLOCKED; нет DIRECT, другой страны или автоматической смены подписки |
| Узел с именем USA отдаёт проверяемый сервис из FI | Не допущен; причина и факт проверки видны |
| Допуск устарел или относится к старому endpoint/подписке | UNKNOWN/недействителен, не основание разрешать обязательный путь |
| ChatGPT US, Google не US/UNKNOWN; затем обратный случай | Узел исключён из AI целиком, никакого среднего балла по сервисам |
| Проверка сервиса не имеет достоверного признака страны | UNKNOWN с объяснением; вся обязательная серия не пройдена |
| Допуск отозван/истёк при недоступном ПК | Заранее установленный enforcement прекращает передачу и активные соединения без новой административной записи/рестарта |
| P2P через выделенный прокси с ai/bypass/обычного устройства | Только подходящий P2P-разрешённый VPN; если его нет — BLOCKED |
| P2P, неидентифицированное или неразрешённое соединение вне прокси | BLOCKED до попадания в AI/bypass/DIRECT; никакой угадывающей пересылки |
| P2P-клиент обходит прокси для UDP/DHT/µTP | Обход блокируется; неподдержанный UDP не объявляется проксированным |
| Известное AI-назначение передано клиентом через P2P-прокси | Ошибочный ingress отвергнут; закреплённый VPN-listener не обходит AI/US-политику |
| Последний исправный конфиг больше не соответствует новой политике | Можно хранить для восстановления, нельзя молча использовать для передачи |
| VPN не имеет FR/SE, но имеет разрешённые NL/DE | Честное предупреждение об отсутствующих странах; допускаются NL/DE |
| Restricted-подписка назначена другой группе/пути | Переименование не отменяет P2P-запрет |
| Туннель/guard/API падает, есть более позднее main/MATCH правило | Запрещённый трафик не проваливается в fallback |
| Два writers; устаревший скан заканчивается позже ручной правки | Поколения сериализованы; новая политика не затирается |
| Ошибка нового архива/переноса на ПК/суммы | Нет изменений; предыдущий архив сохранён |
| Обрыв после установки файла, но до успешного reload | Несоответствие выявлено; известное восстановление, без ложного SUCCESS |
| Read-only диагностика и тест по кнопке | Нет смены production-узла/конфига; видны границы доказательства |
| Отключение AI-DNS при активном полном ai-режиме | Зависимость не исчезает незаметно; безопасный отказ/блокировка |
| Uninstall модуля | Удалены его артефакты, чужие сохранены; базовая защита остаётся |
| Повторное сохранение/миграция/reinstall | Идемпотентность; секреты/нестандартные ключи не теряются |
