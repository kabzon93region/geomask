# Модули geomask: выбор при установке и отдельное обновление

Документ для того, кто ставит geomask на роутер и для того, кто добавляет в него
новый модуль. Описывает ровно то, что реализовано в v1.29.0.

## Что такое модуль

Модуль — часть geomask, которая может отсутствовать на роутере. Каталог модулей —
`modules/index.json`: для каждого модуля версия, тип, зависимости и список файлов
(путь установки → файл репозитория, режим, SHA-256).

Двенадцать модулей:

| id | обязательный | что даёт |
|---|---|---|
| `core` | да | панель, бэкенд, sync, node-audit, обновления |
| `path_vpn` | да | VPN-лейн (основной туннель) |
| `path_vpn_nop2p` | нет | VPN-noP2P (без торрентов) |
| `path_ai` | нет | AI-лейн (Google/OpenAI/Claude) |
| `ai_dns` | нет | DNS-over-HTTPS для AI-устройств |
| `youtube` | нет | watchdog краёв YouTube и списки доменов |
| `torrent` | нет | правила и слушатель для торрентов |
| `diagnostic` | нет | dnscheck, vpnwatch, утренняя проверка |
| `device_modes` | нет | режимы устройств (исключения из туннеля) |
| `backup_share` | нет | SMB-шар с бэкапами |
| `self_update` | нет | самообновление из GitHub |
| `admission_service` | нет | служба допуска AI-устройств |

Обязательные (`GM_REQUIRED_MODULES="core path_vpn"`) ставятся всегда: без `core`
нечего запускать, без `path_vpn` у продукта нет назначения. Остальные можно снять.

## Как выбрать

```sh
sh geomask.sh --list-modules                 # что обязательно, что по выбору
sh geomask.sh --modules=core,path_vpn        # минимальный набор
sh geomask.sh --modules=core,path_vpn,youtube,torrent
```

Интерактивно: при `--reinstall` (и при запуске шага, который что-то ставит) без
`--modules` установщик показывает список и спрашивает номера через запятую.
`Enter` — оставить текущий выбор, `all` — все модули. Обязательные добавляются
обратно, что бы ни было введено. Флаги всегда главнее меню: `--modules` отменяет
вопрос, `--yes`/`--auto`/`--check` тоже (неинтерактивные прогоны не спрашивают).

Выбор запоминается в `/etc/geomask/modules.json`:

```json
{ "selected": ["core", "path_vpn"] }
```

Этот файл — единственный источник правды о том, что роутер должен нести. Его
пишет установщик (`step2_apply` и `step5_apply`), читают панель и помощник
обновлений. Нет файла — считаем, что выбрано всё (так ведут себя роутеры,
установленные до появления выбора).

## Как установщик это исполняет

Два разных механизма, и оба нужны:

1. **Файлы.** `save_stream` перед записью спрашивает `module_skip_path`: путь →
   модуль (`module_owns_path`, карта вставляется при сборке из `modules/index.json`),
   модуль не выбран → файл не пишется, в лог идёт `skip … module 'x' not selected`.
2. **Проверки.** Каждый `stepN_check`, который раньше падал с `_need=1` на
   отсутствующем файле необязательного модуля, теперь сначала спрашивает
   `mod_skipped <модуль>`: для снятого модуля печатает «пропущен: модуль … не
   выбран» и не считается провалом.

Правило, ради которого всё это написано: **установка и проверка должны читать один
и тот же флаг**. Если гейтить только запись, проверка упадёт на своём же пропуске и
прервёт установку целиком.

### Ловушка cron

Запись в cron создаётся в `step5_apply`, а проверяется в `step5_check` — в другом
месте и другим кодом. Поэтому оба конца идут через функции:

```sh
cron_ensure <модуль> <regex-метки> <строка crontab>
cron_verify <модуль> <regex-метки> <подпись> [soft]
```

`cron_ensure` для снятого модуля молчит, `cron_verify` печатает «пропущен» вместо
`bad … _need=1`. Миграция старой записи (`*/5` → `*/1`) остаётся отдельным шагом
перед `cron_ensure` и тоже под условием `module_selected`.

Нельзя «обернуть» один блок и оставить второй: проверка увидит отсутствие записи,
которую создание честно пропустило.

### Ruleset-заглушки

Конфиг mihomo ссылается на `ytdirect.yaml`, `ytvpn.yaml`, `torrentdirect.yaml`
всегда. Если модуль снят, файла не будет и `mihomo -t` упадёт — поэтому
`ruleset_stub <модуль> <путь>` создаёт пустой `payload: []`, но только когда файла
нет: содержимое, оставшееся от прежней установки, не затирается.

## Обновление модулей

Панель → «Модули», RPC `mod_list` / `mod_check` / `mod_update`, на роутере
`/usr/lib/geomask/geomask-module-update.py`. Помощник сверяет SHA-256 каждого файла
модуля с каталогом, качает только изменённое, проверяет хеш до записи, отказывается
перезаписывать локально изменённый файл без `--force`, пишет через временный файл и
откатывает при сбое.

Снятый модуль помечается состоянием `not-selected`: он виден в списке (не прячется
молча), кнопка «Обновить» заблокирована, `update` для него отказывает — менять
набор модулей должен установщик, а не помощник.

## Добавить новый модуль

1. `modules/<id>.json` — манифест (версия, тип, зависимости, имя).
2. Файлы модуля — блоками `save_stream <путь> <режим>` в `geomask.sh.in`.
3. `GM_ALL_MODULES` — добавить id; `module_label` — человеческое описание.
4. Если у модуля есть cron — только через `cron_ensure`/`cron_verify`.
5. Если у модуля есть правила в конфиге mihomo — `ruleset_stub` для случая «снят».
6. `python tools/build_module_index.py` — перегенерировать каталог.
7. Тесты: `tests/run_tests.sh` (песочница) и `tests/test_module_update.py`.

## Проверка

```powershell
cd Y:\openwrt\geomask
C:\Python\Python314\python.exe build.py
C:\Python\Python314\python.exe tools\check_build.py
C:\Python\Python314\python.exe tools\build_module_index.py
C:\Python\Python314\python.exe tools\gen-geo-rpc.py --check
C:\Python\Python314\python.exe -B -m unittest discover -s tests -p 'test_*.py'
& 'C:\Program Files\Git\bin\bash.exe' tests/run_tests.sh
```

`sh -n` проверять только на собранном `geomask.sh`: в шаблоне есть
`@@MODULE_PATHS@@`, он невалиден для shell.
